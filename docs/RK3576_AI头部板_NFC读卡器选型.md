# RK3576 AI 头部板：NFC / RFID 读卡器选型

> 日期：**2026-08-20**  
> 适用板：**RK3576 机器人头部**，PCB 布局非常紧张  
> 主机口：**I2C0（3.3 V）**，再加 GPIO 做中断 / 复位  
> 需求里的「NTC」按 **13.56 MHz NFC/RFID** 处理。  
> **本版推翻上一版「双接口标签、不要上读卡器」**：头部要读卡、读手机、读手环，必须上读卡芯片。

---

## 1. 当前结论

头部要主动读卡：上 **读卡器 / NFC 控制器**，不要再用 FM11NT082C / ST25DV 这类被动标签。

I2C 仍然能保住。RK3576 是 Linux SoC，优先选 **带 NCI 固件的 NFC 控制器**，不要选纯模拟前端再自己写协议栈。

| 优先级 | 怎么选 | 主机口 | 具体料号 | 封装 |
| --- | --- | --- | --- | --- |
| **Linux / 手机生态优先** | NXP NCI 控制器 | **I2C** | 打样 / 量产 **PN7160A1HN/C100**；板更紧用 **PN7160A1EV/C100** | HN=HVQFN40 **6×6 mm**；EV=VFBGA64 **4×4 mm** |
| 还要碰 iPhone 钱包 / ECP | 同上 + Apple ECP | **I2C** | **PN7161A1HN/C100** 或 **PN7161A1EV/C100** | 与 PN7160 同封装、同焊盘 |
| 芯片要最小、射频要强 | ST 高性能前端 | **I2C**（`I2C_EN` 拉高）或 SPI | **ST25R3916B-BWLT** | WLCSP36 **约 3.22×3.21 mm** |
| 国产、便宜、好买 | 复旦微多协议读卡 | **I2C** / SPI / UART | **FM17550-QNA-T-G** | QFN32 **5×5 mm** |
| 不要选 | SPI-only 小封装 | SPI | ST25R100-CMET | 4×4 mm，**没有 I2C** |
| 不要选 | 老料 / 过大 | I2C/SPI/UART | PN532 | 生产头部板不推荐 |

兼容性排序（头部当读卡器，读卡 / 手环 / 安卓 HCE）：

1. **PN7160 / PN7161** — 协议最全，Linux 官方栈，还能卡模拟给手机碰  
2. **ST25R3916B** — 射频最强，小天线更友好，Linux 要自己挂 RFAL  
3. **FM17550** — 国内 14443A/B + M1 够用，**没有 ISO15693**  
4. 标签芯片（FM11NT082C / ST25DV）— **读不了卡**，本需求作废

天线仍是占面积的大头。读卡器还要 **27.12 MHz 晶振 + EMC/匹配网络**，发射电流按 **200～300 mA 脉冲** 预留。  
上一版的 Type 2 / Type 5 **标签料不能和读卡器互换**。

本板接口（读卡器最低集）：

| 信号 | 接到哪 | 说明 |
| --- | --- | --- |
| I2C0_SCL / I2C0_SDA | 3.3 V I2C | 400 kHz 即可；PN7160 支持到 3.4 MHz |
| GPIO_IRQ | 输入，建议上拉 | 有卡 / 有数据必须靠中断，不要轮询 |
| GPIO_VEN / RST | 输出 | PN7160 的 VEN；ST / 复旦微的复位 |
| 可选 GPIO_DWL_REQ | 输出 | 仅 PN7160 下载固件用，可先飞线 |
| VBAT / TVDD | 3.3 V，能供发射 | 与数字 3.3 V 分开走，就近去耦 |

上一版「再加 1 个 GPIO 做场检测」不够。读卡器至少 **IRQ + 复位** 两根 GPIO。

## 2. 先确认能力（标签 vs 读卡器）

| 场景 | 典型用途 | 该不该上读卡芯片 |
| --- | --- | --- |
| 手机碰头部：配对、写 WiFi、读序列号、一碰连 | 标签（Tag）或读卡器的 **卡模拟** | 可以不上读卡器 |
| **头部去读卡、读手机、读手环** | **读卡器（Reader）** | **必须上**，面积和电流都大很多 |
| 两种都要 | 一颗带 **读写 + 卡模拟** 的控制器 | **PN7160 / PN7161 / ST25R3916B / FM17550** 都能兼；不要并两颗射频 |

上一版按「手机碰头部」选了双接口标签，方向对那个场景成立。  
现在明确要 **头部主动读**，标签方案整页作废，改读卡器。

一颗 PN7160 可以同时覆盖两件事：

- **Poll（读卡器）**：读门禁卡、NTAG 手环、安卓 HCE  
- **Listen（卡模拟）**：头部假装成 Type 4 标签，手机仍可「碰一下」读 NDEF

不要在同一块头部板上并一颗标签 + 一颗读卡器：两套 13.56 MHz 天线会互相抢场。

### 2.1 「读手机」不要按读卡理解

| 对方 | 头部当读卡器时 | 头部当卡模拟时（手机当读卡器） |
| --- | --- | --- |
| 实体卡 / NTAG 手环 | 能读（Type 2 / Classic / Type 4，看芯片） | 无关 |
| 安卓手机 | 只有手机开了 **HCE / 钱包卡** 才能被读 | 系统级「碰一下」读 NDEF 最稳 |
| iPhone | **普通 App 不能被头部读成一张卡**；要读钱包需 **PN7161 + Apple ECP** | iOS 读 Type 4 NDEF 可以；后台一碰连仍挑 |

配对、写 WiFi、读序列号：继续走 **手机读头部**（卡模拟出 NDEF），不要指望头部去读 iPhone。  
读工卡、手环、访客卡：走读卡器模式。

## 3. 协议体系（读卡器侧仍要分清）

13.56 MHz 高频里，三层名字不要混：

| 层 | 说的是什么 | 例子 |
| --- | --- | --- |
| ISO/IEC 空中协议 | 射频调制、帧、命令 | ISO14443A、ISO14443B、ISO15693、FeliCa |
| NFC Forum 标签类型 | 手机/读卡器按哪种规格读写 NDEF | Type 1～5 |
| 应用格式 | 里面存什么数据 | NDEF、MIFARE 扇区、私有 EEPROM |

读卡器要声明自己能 **发起** 哪些协议。标签芯片只是其中一种被读对象。

### 3.1 头部读卡器至少要覆盖什么

| 目标物 | 底层 | Forum 类型 | 本板要不要 |
| --- | --- | --- | --- |
| NTAG / 复旦 FM11NT08xC 手环、贴纸 | ISO14443A | Type 2 | **必须** |
| 普通身份证感应区、部分门禁 | ISO14443A/B | Type 4 或专有 | 建议 |
| MIFARE Classic 工卡 / 公交衍生 | 14443A + Crypto1 | 非 Forum 标准 | 国内很常见，**建议有** |
| ICODE / ST25DV / 工业盘点 | ISO15693 | Type 5 | 有更好；FM17550 没有 |
| 安卓 HCE | ISO14443-4 | Type 4 | 要「读手机」就必须有 |
| iPhone 钱包 | Apple ECP | 专有 | 只有 **PN7161** |
| 125 kHz / UHF | 不是 NFC | — | 本板不要 |

### 3.2 上一版两颗标签和读卡器的关系

| | ST25DV04KC | FM11NT082C / 083C | 本版读卡器 |
| --- | --- | --- | --- |
| 角色 | 被动标签 | 被动标签 | **主动发射 13.56 MHz** |
| ISO | 15693 | 14443-A | 由读卡器发起 14443 / 15693 |
| 主机口 | I2C 访问自己的 EEPROM | 同上 | I2C 发 NCI / 寄存器命令 |
| 能不能读别人 | 否 | 否 | **能** |
| 和本版料互换 | 否 | 否 | 否 |

FM11NT082C 不是 ST25DV 的国产替换，更不是 PN7160 的替换。  
要对齐「能被手机碰 + 自己也能读卡」，用 **PN7160 卡模拟 + 读卡**，不要再堆标签。

## 4. 推荐料对比

### 4.1 首选：NXP PN7160（I2C）

适合 RK3576 Linux 头部板的默认答案。

| 项目 | 内容 |
| --- | --- |
| 角色 | NFC **控制器**（片内固件 + NCI 2.0），不是裸前端 |
| 读卡 | ISO14443A/B、FeliCa、ISO15693、MIFARE 1K/4K、Type 1～5 |
| 卡模拟 | Type 3 / Type 4（A&B）；可自主出 NDEF，主机休眠也能被手机碰 |
| P2P | 有（现在很少用） |
| 主机口 | 料号里的 **A = I2C**，B = SPI，**焊盘不兼容，下料就要对** |
| I2C 地址 | 默认 **0x28**，ADR0/ADR1 可选 0x28～0x2B |
| 供电 | 1.8 V 或 **3.3 V**；发射驱动约 **250 mA** |
| 时钟 | 外挂 **27.12 MHz** 晶振（CL 10～12 pF），或主机参考钟 + PLL |
| Linux | 官方 `nxpnfc` 内核节点 + [linux_libnfc-nci](https://github.com/NXPNFCLinux/linux_libnfc-nci)（分支 `NCI2.0_PN7160`） |
| 文档 | 数据手册 PN7160_PN7161；移植 AN13287；卡模拟 AN13861 |
| 不做什么 | **不能做 EMVCo 过检 POS**。要支付过检改 PN5180 / PN5190 / PN7220（基本是 SPI，且更大） |

料号怎么写：

| 用途 | 料号 | 封装 | 备注 |
| --- | --- | --- | --- |
| **打样首选** | **PN7160A1HN/C100** | HVQFN40 6×6 | I2C，好焊、好改 |
| 板极紧 | **PN7160A1EV/C100** | VFBGA64 4×4 | 仍是 I2C；BGA 返修难 |
| 要碰苹果钱包 | 把 `7160` 换成 **`7161`**，后缀不变 | 同封装 | 仅多 Apple ECP |
| 不要买 | PN7160**B1**xx | 同尺寸 | 那是 **SPI** 版 |

C100 / C101 是固件版本。新设计问代理要当前量产固件（常见仍是 C100；已有 C101）。  
评估板：OM27160A1HN / OM27160A1EVK。

RK3576 设备树要点（I2C0，地址按硬件改）：

```dts
&i2c0 {
    status = "okay";
    nxpnfc: nxpnfc@28 {
        compatible = "nxp,nxpnfc";
        reg = <0x28>;
        interrupt-parent = <&gpioX>;
        interrupts = <Y IRQ_TYPE_LEVEL_HIGH>;
        enable-gpios = <&gpioX Z GPIO_ACTIVE_HIGH>;
    };
};
```

用户态用 NXP `linux_libnfc-nci`，不要自己拼 14443 防冲突。

### 4.2 芯片最小：ST25R3916B-BWLT（I2C）

板面积被芯片本体卡死、又要小天线读得动时用。

| 项目 | 内容 |
| --- | --- |
| 角色 | 高性能 NFC **前端**（协议在主机 RFAL） |
| 读卡 | NFC-A/B/F/V，最高 848 kbit/s；ISO15693 到 53 kbit/s |
| 卡模拟 | NFC-A、NFC-F |
| 额外 | DPO、AWS、噪声抑制、**自动天线调谐 AAT**、LPCD |
| 主机口 | SPI 默认资料多；**I2C 要把 `I2C_EN` 拉到有效电平** |
| 供电 | 2.4～5.5 V，IO 1.65～5.5 V，可直接挂 3.3 V I2C0 |
| 封装 | **ST25R3916B-BWLT**：WLCSP36 ≈ 3.22×3.21 mm |
| 次选封装 | ST25R3916B-AQET：UFQFPN32 **5×5 mm**（更好焊） |
| 软件 | ST RFAL；Linux 没有 PN7160 那种官方 NCI 栈 |
| 不要用旧硅 | ST25R3916（无 B）还能买，新设计用 **3916B** |

WLCSP 比 PN7160 BGA 还小一圈，但 RK3576 上要自己维护轮询、防冲突、NDEF。  
小天线、金属壳体、喇叭/摄像头旁边，3916B 的输出功率和 AAT 比 PN7160 更抗。

### 4.3 国产 I2C：复旦微 FM17550

供应链要国产、只读国内常见卡时用。

| 项目 | 内容 |
| --- | --- |
| 料号 | **FM17550-QNA-T-G**（卷带）/ FM17550-QNA-A-G（托盘） |
| 封装 | QFN32 **5×5 mm** |
| 主机口 | **I2C** / SPI / UART，接口电源可独立 |
| 读卡 | ISO14443A/B，FeliCa，**M1 硬件加密** |
| 卡模拟 | 14443A / FeliCa |
| P2P | NFCIP-1 |
| 没有 | **ISO15693 / Type 5**（手册主规格不列；经销商页面有的不要信） |
| 时钟 | 27.12 MHz 晶振 |
| 电压 | 2.2～3.6 V，发射脚可到 5.5 V |
| 读距 | 手册典型到 50 mm，看天线 |
| 软件 | 寄存器级，类似 RC522/PN532；**无 Linux NCI** |
| 公开资料 | **弱**：官网基本只有产品说明书；原理图 / 天线匹配 / 完整驱动要找代理 |
| 货 | LCSC 常见，打样容易 |

更低成本、只要 Type A：FM17522-QNA（同样 QFN32、有 I2C、有 LPCD）。  
只要 Type A 且接受 SPI：FM17510 是 QFN16，更小，但 **不是 I2C**。  
金融 POS 过检：FM17660 系列，本板用不上。

### 4.4 明确不选

| 料 | 原因 |
| --- | --- |
| FM11NT082C / 083C / ST25DV04KC | 标签，读不了别人 |
| ST25R100-CMET | 4×4 好看，**只有 SPI** |
| PN532 | 老、封装大、Linux 集成差，只适合评估模块 |
| PN5180 / PN5190 / CLRC663 | 读卡很强，主流是 SPI，软件重 |
| PN7642 | 片内 Cortex-M33，头部已有 RK3576，浪费 |
| 125 kHz / UHF 读头 | 不是手机 NFC |

### 4.5 设计资料 / 开源 / 原理图（三颗料差很多）

按「能不能直接抄着画板、Linux 上直接编」排序：**PN7160 ≫ ST25R3916B ≫ FM17550**。  
FM17550 你的判断对：公开侧几乎没有能当参考设计用的原理图和开源栈。

| | **PN7160** | **ST25R3916B** | **FM17550** |
| --- | --- | --- | --- |
| 数据手册 | 公开 [PN7160_PN7161](https://www.nxp.com/docs/en/data-sheet/PN7160_PN7161.pdf) | 公开 [DS13541](https://www.st.com/resource/en/datasheet/st25r3916b.pdf) | 官网「产品说明书」可下；完整手册常要登录/代理 |
| 硬件设计指南 | **AN12988**（含典型应用原理图） | 数据手册第 2 章 + AN；评估板当参考 | **没有**对等的公开 HW design guide |
| 天线 / 匹配 | **AN13219** + NXP Antenna Design Tool | AN5264 等天线笔记 + AAT 说明 | 手册里几页典型值，无计算器、无调谐流程 |
| **可抄原理图** | **UM11496** 里 OM27160 整页原理图；设计包 **[HW6635](https://www.nxp.com/doc/HW6635)**（原理图 + BOM + Gerber） | STEVAL-25R3916B / X-NUCLEO-NFC08A1：**PDF 原理图 + Gerber + Altium** 在 st.com CAD | **官网不放**；立功/复旦代理项目包才有。网上 GitCode「原理图分享」是转载，不能当量产依据 |
| 评估板 | OM27160A1HN / A1EVK（I2C） | STEVAL-25R3916B、X-NUCLEO-NFC08A1 | 立功有 FM175xx 开发套件，要申请，不公开 Gerber |
| **Linux 开源** | **完整官方栈**：内核 [nxpnfc](https://github.com/NXPNFCLinux/nxpnfc)，用户态 [linux_libnfc-nci](https://github.com/NXPNFCLinux/linux_libnfc-nci)（分支 `NCI2.0_PN7160`），移植 **AN13287** | 官方是 **RFAL 用户态移植** [STSW-ST25R013](https://www.st.com/en/embedded-software/stsw-st25r013.html)（样例走 **SPI + 树莓派**，I2C 要自己改）；社区内核 [pguyot/st25r391x](https://github.com/pguyot/st25r391x) 仅 I2C | **没有**官方 Linux 驱动，也没有 NCI。MCU 示例（STM8/STM32）靠代理 Demo 或民间仓库，质量参差 |
| MCU / 裸机 | AN13288 NCI 例程 | **X-CUBE-NFC6**、STSW-ST25RFAL002、UM2890（RFAL 最完整，但是 STM32 味道） | 代理 Demo：寄存器读写 + 14443 状态机 |
| Android | AOSP / nxp-nfc-infra 有 PN7160 | 无现成 AOSP NFC HAL | 无 |
| 设备树 | `compatible = "nxp,nxpnfc"` 直接挂 | 无主线绑定；要自己写 | 无 |
| 本板工作量 | 抄 HW6635 电源/晶振/EMC，改天线尺寸 | 抄 STEVAL 射频，软件把 RFAL 从 SPI 改到 I2C0 | 先向复旦/立功要「FM17550 参考原理图 + 驱动包」，否则硬件和协议都从手册抠 |

要点：

- **PN7160**：设计资料和开源都是官方、成套的。画板抄 AN12988 / HW6635，软件抄 AN13287。料号 **A=I2C、B=SPI**，原理图能抄，芯片不能买成 B1。
- **ST25R3916B**：硬件资料同样公开、能下到 Altium。软件不缺，但缺的是「Linux SoC + I2C」这一条现成路：官方 Linux 包按 SPI 写，RFAL 要自己接到 RK3576 的 I2C0。比 PN7160 重的是软件，不是没原理图。
- **FM17550**：LCSC 好买不等于资料好拿。复旦官网产品页对 FM17550 只挂说明书，**不提供** NXP/ST 那种公开原理图包、Gerber、天线工具、GitHub 协议栈。完整参考设计走销售/FAE。GitCode 上的「FM17550 开发资料 / 原理图」是民间汇总，版权和正确性都无法当开源方案。RK3576 上等于从寄存器手册自己写读卡器。

因此：要公开原理图 + 开源 Linux，不要把 FM17550 当默认。它只适合「已经能从代理拿到包、只读国内 14443/M1」的产线。

## 5. 和上一版协议结论怎么衔接

上一版比的是 **标签被手机读**。Type 2 确实比 Type 5 兼容。  
这一版比的是 **头部去读别人**，排序改成：

| 要读的对象 | 读卡器侧协议 | 推荐芯片够不够 |
| --- | --- | --- |
| Type 2 手环 / 贴纸 | ISO14443A | 三颗推荐都够 |
| Type 4 / 安卓 HCE | ISO14443-4 | PN7160、3916B 原生；FM17550 要自己走 14443-4 |
| Type 5 / 工业标签 | ISO15693 | **只要 PN7160 或 3916B** |
| MIFARE Classic | 14443A + Crypto1 | PN7160、FM17550 有硬件；3916B 走底层模式 |
| 手机系统「碰一下」配网 | 不靠读手机，靠 **卡模拟 NDEF** | PN7160 最省事 |

两种 ISO 仍然不能当同一套命令用。读卡器固件会分别 poll NFC-A / NFC-B / NFC-F / NFC-V。  
天线都是 13.56 MHz 线圈，匹配网络按读卡器（差分 TX + EMC）做，**不能复用标签那套两脚小线圈参考**。

## 6. 面积、电源、天线（紧张布局的真实占用）

芯片本体不是大头。读卡器最小可落地的一组是：

| 块 | 大约占用 | 说明 |
| --- | --- | --- |
| 芯片 | 4×4 ～ 6×6 mm | BGA/WLCSP 再小也要外围 |
| 27.12 MHz 晶振 | 2.0×1.6 或 1.6×1.2 mm | 紧贴芯片，远离开关电源 |
| EMC + 匹配（L/C） | 8～15 颗 0402/0201 | 差分两臂对称 |
| 去耦 | 5～8 颗 | VBAT / VDD(PAD) / TX 分开 |
| **天线** | **建议 ≥ 15×15 mm 净空；舒服值 25×25～40×40** | 小于 12×12 读距会掉到贴脸 |
| 金属净空 | 线圈内、下层尽量挖空 | 喇叭、摄像头、钢片、电池都会吞场 |

发射时 VBAT 会拉 **百毫安级** 脉冲。  
3.3 V 从 RK3576 电源树单独分一档，电感后就近 10 µF + 100 nF，不要和摄像头、功放共一颗远电感。

小天线策略：

- 优先 **ST25R3916B**（功率和 AAT）  
- 或 PN7160 把线圈做到外壳/镜片 FPC，芯片仍在头部主板  
- 不要指望 8×8 mm 板载线圈稳定读工卡

## 7. 本板接法（按 PN7160 I2C 画）

```
RK3576 3.3 V I2C0
   SCL ──────────── I2C_SCL
   SDA ──────────── I2C_SDA
   GPIO_IRQ ←────── IRQ
   GPIO_VEN ──────→ VEN          （低电平硬关机）
   GPIO_DWL ──────→ DWL_REQ      （可选）
   3.3 V ────────── VBAT, VDD(PAD)
   GND  ─────────── EP / VSS

PN7160
   XTAL1/XTAL2 ── 27.12 MHz + 两颗负载电容
   TX1/TX2 ── EMC ── 匹配 ── 板载或 FPC 线圈
   ANT1/ANT2 ── 接收
```

ST25R3916B：`I2C_EN` 接高选 I2C，SDA/SCL 接 I2C0，IRQ 接 GPIO，另留复位。  
FM17550：I2C 使能脚按手册拉好（和 SPI/UART 三选一），IRQ + RST 同样要。

I2C 地址避开总线上已有从设备。PN7160 默认 0x28。

## 8. 软件落点（RK3576 Linux）

| 芯片 | 内核 | 用户态 | 工作量 |
| --- | --- | --- | --- |
| **PN7160/61** | `nxp,nxpnfc` + `/dev/nxpnfc` 或 alt-i2c | [linux_libnfc-nci](https://github.com/NXPNFCLinux/linux_libnfc-nci) | **最小** |
| ST25R3916B | 无官方主线 NCI；SPI 样例见 STSW-ST25R013，I2C 可参考 [st25r391x](https://github.com/pguyot/st25r391x) | ST RFAL（X-CUBE-NFC6 / STSW-ST25RFAL002）移植到 I2C0 | 中 |
| FM17550 | 无公开驱动 | 代理 Demo 或自写 14443 状态机 | **大，先确认能要到资料再选型** |

功能建议分两个守护进程状态，不要同时猛发场：

1. **读卡循环**：poll Type A/B/F/V → 上报 UID / NDEF / Classic 扇区  
2. **被碰循环**：卡模拟 Type 4 NDEF（序列号、配网 URL）  
3. 或 PN7160 配置成 listen+poll 自动切换（官方栈支持）

## 9. 打样清单（按推荐顺序只备一种）

**方案 A（默认，Linux 头部板）**

这不是两块功能一样的板，也不要买两套焊到产品上。

| 料号 | 是什么 | 干什么 | 产品要不要 |
| --- | --- | --- | --- |
| **PN7160A1HN/C100** | **芯片**（HVQFN40，一卷/一盘 IC） | 焊在 RK3576 头部板上 | **要，这才是量产料** |
| **OM27160A1HN** | NXP **评估小板**（上面已经焊好一颗 PN7160A1HN + 40×40 mm 天线 + 晶振 + 匹配） | 软件先在开发板上跑通 I2C / `linux_libnfc-nci` | **不要进产品**；实验室可选买一块 |
| OM27160A1EVK | 评估套件 | 小板 + Arduino/树莓派转接板 + 一张样卡 | 只有手头没有转接线时才买套件 |

关系：评估板上那颗硅就是 PN7160A1HN。功能相同的是 **芯片**，不是两块板。

要不要买评估板：

- **头部板还没画完 / 想先调 Linux 驱动**：买 **一块** OM27160A1HN（或 EVK），杜邦线/转接接到 RK3576 开发板的 I2C0 + IRQ + VEN。和画板并行，少等一轮空板。
- **直接在第一版头部板上调**：评估板可以不买。风险是天线、匹配、晶振、电源若有问题，会和软件问题缠在一起。
- **不要**买两块评估板，也 **不要** 在头部板上再叠一块 OM27160。

产品侧只备：

- IC：PN7160A1HN/C100（I2C，HVQFN40）  
- 晶振：27.12 MHz，CL 10～12 pF，例如 NDK NX2016SA 或村田 XRCGB27M120  
- 天线：第一版 25×25 mm 矩形，2 圈，远离金属；壳体允许再加大

**方案 B（芯片最小）**

- IC：ST25R3916B-BWLT  
- 打样焊接无把握时改 ST25R3916B-AQET（5×5 QFN）  
- 软件按 RFAL + I2C，不要抄 PN7160 设备树

**方案 C（国产）**

- IC：FM17550-QNA-T-G  
- 只承诺 14443A/B + M1 + 卡模拟  
- 要 Type 5 就不要走这条

同一块 PCB 不要同时打 A+B 两套射频。天线匹配按选定芯片各做一套。
