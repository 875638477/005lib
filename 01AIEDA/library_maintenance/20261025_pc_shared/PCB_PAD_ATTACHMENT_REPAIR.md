# 公共封装替换后的真实走线附着修复

适用于已布线 Allegro 17.2 板：新封装引脚位置发生已批准的小幅变化，旧走线仍落在新焊盘铜内，但数据库原生连接已经分离。

## 已验证结果

本工程 34 个 SOT23_123 改为公共 sot23-3 后，全部 6521 个引脚的网络、批准位置和封装属性都通过；旧走线的 228 个端点也都在新焊盘内。然而原生 GetConnect 分区由 2020 增至 2109，52 个网络的连接状态改变。因此「端点在铜内」「网表日志零错误」「引脚网络名相同」都不能代替真实连接验证。

在新副本一次补入 92 条焊盘内部短线后，新进程重新打开并独立核验：全部 6521 个物理引脚、2020 个连接分区的完整成员多重集、1118 个网络状态与源板一致。全部 1066 个器件的文字、姿态和属性也保持批准结果。该结论对应工程验证记录 `verification/sot34_connectivity_full4/SOT34_COMPLETE_TYPED_CONNECTIVITY_REVIEW.json`；先前失败候选和报告保留。

## 操作步骤

1. 冻结源板、目标库和完整逐物理引脚表。必须区分原生 nil 网络、空字符串 NC、重复编号和空编号机械焊盘。只在新工作副本操作。
2. 在替换前导出每个目标引脚的 `axlDBGetConnect(pin t)` 真实邻居，以及邻接路径的网络、层、宽度和每段端点。替换后导出同样的内容，并比较完整引脚分区。
3. 只修复源板确实有同网走线邻接的引脚。选取该真实路径上的旧端点，连接至新引脚中心；没有源邻接的孤立脚不能凭网络名造铜。本案例 Q62.3 只有网络名、源邻居为空，明确跳过。
4. 短线宽度取 5mil 与原线宽的较小值。用 `axlPathStart` 生成候选路径，再用 `axlPolyFromDB(path ?line2poly t ?endCapType 'ROUND)` 得到完整带圆端铜形；以新引脚在实际目标层的 `axlPolyFromDB(pin ?layer layer ?padType 'REGULAR ?holes t)` 铜形做原生 ANDNOT。仅差集为空才允许创建。不能只用中心或包围框判断。
5. 写入前一次预检全部清单，任何一项失败都不写。用 shape 范围的 `axlDBCloak` 成批 `axlDBCreatePath`，保留全部原走线。每条创建后刷新数据库对象，再核实新引脚有真实原生邻居。
6. 保留原 DRC 状态、完整实例文字和姿态。保存后必须新进程打开，再核全板逐物理引脚、完整连接分区成员多重集、网络状态和规则。分区总数相同本身也不够。

## 线路实体被原生合并时

Alt/ECO 可能将两条共线线段合并为一条更长线段，源线段实体不再逐项相同，但铜没有丢失。此时允许严格的区间并集证明：当前实际数据库中的线段必须同网、同层、同宽；按设计声明的 mils2 网格转整数，使用精确叉积判共线，再验证原源线段的完整区间被这些实际线段的并集覆盖。端点方向可以相反；不允许按距离、包围框或宽泛容差放行。圆弧仍保持完整原实体匹配。

已验证实例 Q73.1：原段 `(2316.3,1377.6)–(2388.7,1450)` 被当前同网 TOP、20mil 的长段 `(2308.7,1370)–(2388.7,1450)` 完整包含。第一版精确实体检查失败，第二版严格区间证明通过；失败证据未覆盖。

## 可复用实现

工程工作脚本为 `w/pcb_migration/sot34_migration/sot34_repair_stubs_v2.il`，生成方法为同目录学习库中的 `prepare_sot34_stubs.py` 与 `prepare_sot34_stubs_v2.py`。源/目标邻接导出由 `prepare_sot34_adjacency_probe.py` 生成。它们包含本项目冻结路径和数量，复用于新项目时必须重新生成清单、绑定输入 SHA，并保留完整新进程门禁，不能直接套用 92 这个数量。

这里证明的是批准封装迁移后的连接恢复。它不替代制造 DRC、时序、电源完整性或整板签核。
## 补充：先保留原铜，再修数据库附着

本轮其余50个器件迁移中，原RTL器件有7段真实symbolEtch铜桥，普通新焊盘无法容纳旧线端的完整短段。处理方法不是放宽“新短段完全位于新pad内”的范围，而是从冻结源板原生复制真实旧铜，作为工程自有的同网铜形保留；公共通用封装仍保持干净。方法与原始网络标签恢复见 `PCB_SOURCE_COPPER_RESTORE.md`。

恢复源铜并只读重取邻接后，最终剩余77个源路径分支去重为73条pad内短段。新短段的完整带宽实体都经原生ANDNOT证明位于新pad内；源线若被合并、截段或转为铜形，允许以“完整原线带宽实体由当前同网实际铜覆盖”代替旧数据库段ID一致，但只适用于冻结原生源线，不能凭bbox允许任意位置。过孔须连同孤立分支独立遍历；本案全部4541个过孔的XY、pad、网络类型及属性在短段操作前后完全相同。

不要为了保持原生分组数量而人为切断已有的同网电源铜。本案U5.3在原PST已属于VDD10_1的11个节点之一，原8mil线与另一条15mil同网线实体已有正面积重叠，但旧GetConnect把它们分成1脚与10脚两岛。源铜子集锚点没有新增物理铜，却修复了数据库附着。该唯一修复采用明确的1+10→11有界接受清单；保留原“要求2020组完全一致”的失败报告，不泛化忽略其它网络或其它分组变化。最终其余1117个网络状态及全部引脚网络类型仍须严格核对。
