# 冻结库导出路径与实际公共路径的有界校验

本记录是发布准备与校验方法，不表示公共库已替换或整个工程已完成。

COMMON_PC 的旧冻结 XML 是从 `capture_stage/COMMON_PC.OLB` 原生导出的，所以根节点 `Lib/Defn/@name` 记录的是该临时路径。后续 staging 校验器原先要求所有冻结 XML 的根名称都等于当前公共路径，因而在完整内容比较前拒绝了这份 XML。候选库重新打开的名称与候选实际文件路径一致。

原失败报告保留。修正使用新的校验器，不修改旧 XML、原库、候选库或旧校验器，也不全局忽略名称。

新门只允许清单中明确的这一条来源身份差异，且先同时验证：

1. 冻结 XML 的路径和完整 SHA 与原 case 一致，其根名称精确等于已记录的原生打开路径。
2. 原生打开的 stage 库与真实公共原件当前完整字节相同，均为原 case 记录的 SHA。
3. 原生导出作业完成、退出码为零、源文件前后保护 SHA 相同。
4. 独立进程的实录 argv 明确指定这份 stage 库和这份 XML 的输出目录；原生身份记录注明只读、零次保存。
5. 所有证据文件自身 SHA 均与冻结清单一致。

这些条件通过后，只在内存中归一这一个根路径，再保留既有完整有序库比较、精确 PCB Footprint 字段逆转、24×14 字体字段与 primitive 默认设置验证。Package 内部名称、图形、引脚、字体、属性及未知字段均不放宽。

实现位于 `bounded_common_identity_checker13/`。`actual_review_v2/PUBLIC_OLB_STAGE_REVIEW.json` 已实际通过原有 10 类反控；`identity_negative_controls/IDENTITY_NEGATIVE_CONTROLS.json` 的额外 6 类身份反控全部拒绝，包括源 SHA、公共路径、XML 根名称及原生 argv 的打开路径、输出目录不匹配。

复用到其它转换时，来源清单必须由那个工程的真实原生作业和当前源字节生成，不能照抄本案例的路径或 SHA。若不能证明两份库完全同字节，则不能将身份归一作为通过理由。实际公共文件发布后仍需从真实公共路径重新打开，并对其内容与最终设计 Cache 做完整同源校验。

13 库发布器 `publish_exact_public_olbs.py` 接受冻结的 13 文件清单，逐一核原件、候选、严格证明和备份 ZIP，先对六个公共根目录做完整清单及 SHA 检查。每次发布是一个独立目录项的原子替换，不在原 inode 上改写，保护其它硬链接名称；13 次替换并不被宣称为一个整体原子事务，部分失败会保留日志和原件 ZIP。发布后的预期 guard 从旧 guard 显式替换这 13 条 SHA 和大小，其它条目保持原值，再用实际全库扫描核验该预期。不得把新的扫描结果直接接受为新的基准。
