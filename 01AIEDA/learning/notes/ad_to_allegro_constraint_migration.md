# AD 规则迁移到 Allegro：操作与验收

本文只记录可复用的方法，不记录某个工程的完成状态。实际输入、映射表、工作板、配置、日志和验收结果放在 `<工程根>`。先完成[转换与连接核验](ad_to_cadence_gui_workflow.md)，再迁移规则；网表一致不代表规则已经迁移。

## 1. 固定输入并导出源规则

1. 确认哪一份 AD 工程是本次权威输入，保存原件，在独立副本操作。另存产生的新版规则、附加默认字段或新分组，不能自动当作原工程已有内容。
2. 在 AD 规则编辑器逐类检查启用状态、优先级、作用域、单位和数值。分别记录两个作用域表达式、指定层、对象类型，以及最小／首选／最大值。
3. 导出或保存完整规则报告；同时保存网络、网络类、差分对、等长组及实际成员。没有显式组对象时如实记录，不能仅凭网名就写成“原 AD 已建组”。
4. 把查询表达式展开成实际网络、物理脚或几何对象集合。对源网络改名、串联器件两侧及跨页名称，使用物理位号和脚号映射证明对应关系。
5. 检查目标板是否已经有约束集、直接属性覆盖、区域规则和分析开关。保存修改前的原生读回，避免用新规则无声覆盖原有例外。

源值为零、字段缺失、规则禁用和不限长是不同状态。必须查清字段语义；不能把所有零值统一解释为无限制。

## 2. 建立规则映射表

| 源内容 | 目标处理与核对重点 |
| --- | --- |
| 线宽规则 | Physical CSet 与实际分配；分清普通宽度、颈宽、颈长、允许层及过孔列表 |
| 铜间距规则 | Spacing CSet 与必要的类间矩阵；分别核对线、焊盘、过孔、形状及同网项目 |
| 差分线宽／间隙 | 真实 Differential Pair 加对应物理／电气约束；层变化和最小／首选值分开 |
| 差分内部长度差 | 对同一对的两条路径单独定义；与跨差分对匹配分开 |
| 等长要求 | 真实 MatchGroup、成员、路径类型、Delta、Tolerance 与检查模式 |
| 串联器件两侧完整路径 | 先确定是否需要 XNet／明确 PinPair，并证明实际端点及器件模型关系 |
| 区域、板边、孔、开槽或特殊对象规则 | 按实际对象类型核对可用规则；没有等价项时单列，不用普通线间距代替 |

AD 可以让同一网络属于多个分类。Allegro 的同一约束域中，每个对象只能属于一个 NetClass；需要按有效优先级编译分类，或使用明确的直接覆盖／类间关系。MatchGroup 则可以重叠，同一成员可以有多组匹配要求，两者不能混用。

把“定义了 CSet”“给类分配了 CSet”“网络实际继承了该值”分别记录。查询一套 CSet 的数字，不能证明目标网络正在使用它。

### 铺铜连接规则另查实际形状作用域

分别核对网络、层、动态边界以及通孔引脚、贴片引脚、过孔的连接类型。源规则只对部分网络或层使用热焊盘时，不能用全局动态形状参数代替局部作用域；负片电源层规则也不能直接当成正片动态铜规则。

直连／热连接、辐条数量、方向、宽度和铜间隙应分别映射。目标的 Oversize 是额外放大量或覆盖值，不能直接当作源绝对间隙；必须查清实际间距基础，并在可丢弃副本生成铜、测量真实 void 边界后确认。未证明等价的字段保留为残余，不为了凑数字强行组合。

本机属性帮助中的 DYN_FIXED_THERM_WIDTH 可覆盖 DRC 或形状参数中的热连接宽度设置，同时会抑制动态铜热连接线的最小线宽 DRC。使用这类属性时应记录该检查语义，不能把参数保存成功当作宽度违规检查已通过。只保存参数而保持原铜时，还不能称现有铜已经符合新热连接要求。

源热焊盘图样的辐条数量，不自动等于目标工具的“最少存活连接数”。没有源独立最小值依据时，可按经确认的策略保留目标原有最小值，并明确它不是源规则值。目标无法放下所需的最少热连接线时，可能不给该引脚或过孔生成任何热连接。不能为了消除断接擅自改动已确认要求；首次重铺后应逐脚检查真实铜连通分区，并把局部几何冲突交由设计者确认。

动态形状局部参数不一定进入 Constraint Manager 的 DCFX／TCFX。导出后实际检查内容，并在未包含这些参数的同源板副本回载；缺失的实例参数需随板文件和明确的恢复方法交付，不能宣称仅靠约束文件就能完整恢复。

## 3. 补建接口分组时保留依据

原工程未建组、但用户要求按接口整理时，记录为新建的 Cadence 分组，并保存成员和语义依据。

- DDR 数据按源符号的真实 DQ 引脚功能及物理脚映射划分 byte。位序可能在 byte 内交换，不能只按目标网名的连续编号猜分组。DM／DBI 只有存在真实引脚与网络时才加入。
- 每个数据 byte 与对应 DQS 对建立关联；数据匹配、DQS 两条路径的匹配，以及 DQ 到 DQS 的参考路径时序分别说明。
- 地址／命令、返回状态信号和时钟分开检查。独立时钟对不自动合成跨时钟等长组。
- PCIe、PEG、DMI 等接口的发送和接收分开，方向以源器件引脚功能证明。不同独立端口不能仅因编号相邻就并为一个多 lane 链路。
- 跨 lane 如采用正 leg 代表路径，明确写成“正 leg 代表路径匹配”。它不等于差分对平均长度匹配，也不替代每对内部的要求。

暂沿用源容差时标记为临时迁移值，保留可修改入口。正式时序要求应结合实际控制器、拓扑、封装延迟、层叠与适用指南确认，不能把源值或工具默认值称为接口规范已满足。

逐组确定原厂预算、处理型号矛盾、DQ↔DQS／CA↔CK、跨串联器件路径和 ps／mil 换算的步骤见[按原厂资料确定接口等长与时延预算](vendor_timing_budget_method.md)。未取得适用数值时保持待定，不自动把迁移容差改为另一套经验值。

## 4. 在 Constraint Manager 建立真实对象

打开本机 Constraint Manager，先核对单位，再分别处理 Physical、Spacing 和 Electrical 工作表。具体入口和可用字段以本机产品等级、版本与 Help 为准。

1. 建立并命名 CSet，填写逐层规则；再建立所属约束域的 NetClass，加入确切成员并分配 CSet。
2. 需要类间间距时建立正确域的类间关系。保存前检查两个端点确属所需域，不以名称相似代替域核验。
3. 创建 Differential Pair，明确正、负成员。成对后再次检查成员没有跨到串联器件的另一侧或同名分支。
4. 在 Electrical 的 Relative Propagation Delay 工作表选中实际 net、XNet 或 PinPair，通过 **Objects → Create → Match Group** 建组；加入完整成员。
5. 明确设置路径类型、Delta 和带单位的 Tolerance。纯匹配时空 Delta 与显式零 Delta 的分类语义不同，不能随意互换。
6. 打开对应分析模式，包括实际使用的相对传播延迟检查。创建分组或填数值，不会自动证明检查已经启用。

### 路径类型必须写清楚

| 类型 | 官方含义 |
| --- | --- |
| L:S | Net／XNet 上最长 PinPair |
| D:R | 最长 driver 到 receiver 的 PinPair |
| AD:AR | 所有 driver 到 receiver 的 PinPair 组合 |

官方属性说明中，AD:AR 找不到 driver／receiver 组合时按仅组／容差格式处理。它适合明确选择这类路径比较的新组，但不能据此宣称与 AD 的总铜线长度相同。

不要把路径类型留空后依赖导入时的隐式默认。原生导入可能把空类型补成 AD:AR；应提前选定并明确记录，使导出、回载和读回采用同一语义。

需要批量处理或 GUI 无法可靠覆盖时，请技术支持使用本机公开原生接口。在独立副本先校准创建、成员、属性与保存重开；不能只依据接口返回非空就判断成功。部分接口以零表示成功，部分返回布尔值或包含失败项的列表。

### 差分最小间距不能放宽源规则

Cadence 的差分 **Minimum line spacing** 以及直接属性 **DIFFP_MIN_SPACE** 可以接管对内制造间距；两者未设置时才回退到所属 Spacing CSet 的 Line to Line。不能认为填了普通线间距，差分对就一定受到同样的下限保护。

1. 按实际作用域和优先级合并源间距、源差分最小间隙及目标实际生效的间距，得到这两条线必须同时满足的下限。不要用全板最高值代替实际作用域。
2. 同步核对 Physical 的差分间隙、Electrical 的 Minimum line spacing 和直接属性覆盖。目标下限不得低于源有效要求；单位换算和网格量化应向安全方向取整，不能四舍五入后放宽。
3. **Coupled Tolerance (-)** 是相对 Primary Gap 的减量，不是绝对最小间距。官方给出的关系为 **Primary Gap − Coupled Tolerance (-) > Minimum line spacing**；根据实际合并下限限制这个减量，并给设计网格保留适当余量。
4. Neck Gap 也不能低于制造下限。如果首选间隙、容差和下限无法同时满足，列出冲突并调整经确认的目标；不能通过降低下限换取通过。
5. 写入后从真实两条成员网络读回有效值，在可丢弃副本验证对内间距违规确实被检出。只检查普通 Line to Line 或只读 CSet 定义不够。

本机官方属性帮助可检索 DIFFP_MIN_SPACE、DIFFP_PRIMARY_GAP、DIFFP_COUPLED_MINUS 与 DIFFP_NECK_GAP。

## 5. 保存、重开并逐项读回

1. 保存到新工作板，关闭后独立重开。对于原生 Constraint Manager 数据更新，保存可能触发向板数据库的展开；保存前的即时对象数不一定是最终结果。
2. 比较所有组名、真实成员类型和成员集合。加入一个已属 XNet 的 net 时，目标成员可能提升为 XNet，必须查明，不能只检查输入列表。
3. 读取每个组默认值、每个成员的实际继承值及直接覆盖。重叠 MatchGroup 应保留各自的成员要求，不能用扁平属性覆盖其他组。
4. 按网络和层逐项读取实际生效的物理／间距值、来源 CSet 和例外；检查类间表、区域规则与分析模式。
5. 核对器件、物理脚网络、放置、已有走线、过孔、形状和层叠。规则迁移不应无意改动它们。

空组可能在保存时被删除。仅有组名、界面出现一行、保存成功或进程正常退出，都不够证明成员与约束已经落实。

保存还可能自动重算动态铜。即使此前 netrev 零错误、关闭了 DRC 且 Unrouted 数量没有变化，也可能有引脚脱离原铜连接；NO_RAT 等属性会使这类变化不体现在飞线统计中。对规则导入副本，应在操作前后与保存重开后逐物理脚比较实际铜连通分区，并保留变化明细。几何包围框、摘要哈希和逻辑网表一致不能单独证明物理连通保持。临时禁止填充再恢复是否安全，必须由独立副本的实际读回证明。

## 6. 原生导出并验证回载

在 Constraint Manager 中分别使用本机帮助确认的入口：

- **File → Export → Constraints**：导出设计约束 DCFX。
- **File → Export → Technology File**：导出技术文件 TCFX。
- 回载分别使用对应的 **File → Import → Constraints／Technology File**。

TCFX／传统 TCF 不能单独代替设计中的完整 net、pair、MatchGroup 和分配关系。交付时同时保留完整设计约束、技术配置、实际工程与必要的原生读回；不要手写或改扩展名冒充导出文件。

回载验收按以下顺序进行：

1. 从同一网络基准建立一个新的独立板副本。要证明导入会创建对象，目标应没有待验证的新分组，不能只在已有相同成员的板上测试。
2. 导入原生导出的配置，保存为新板，再独立重开。检查完整导入日志、模式、分组、成员、单位及继承。
3. 从回载后的板再次原生导出 DCFX／TCFX，比较完整规则内容；不能只比较文件根标签或文件大小。
4. 对有名字的对象与属性按名称／类型比较，保留重复数量；MatchGroup／NetClass 成员可按集合核对。差分对正／负成员顺序、实际有序的层叠和数值列表必须保留，不能用统一排序掩盖极性交换。
5. 文件名、设计自身名称及原生修订计数如变化，逐项列出真实前后值作为元数据。不能静默过滤其他字段，也不能用“元数据变化”解释实际规则数值变化。

原生接口可在隔离副本完成同样的导出／回载流程；这不代表当前 GUI 菜单已经实操验证。

DCFX／TCFX 不是已布铜板文件的替代备份。完整约束回载后规则可以逐项相等，同时动态铜已经变化。临时禁用填充、保存、独立重开并恢复填充的保护流程，必须针对实际导入命令验证；不能把网表导入的成功经验直接外推到约束配置导入。

因此分别判定“完整配置恢复”和“已有物理铜保持”。后者须检查包含自动生成铜的真实图元，并逐物理脚比较铜连通分区。规则恢复通过但铜发生变化时，保留这两项独立结论，原已布铜 BRD 继续作为几何备份；不能用回载候选替换它并宣称物理等价。

## 7. 检查规则是否真正作用

先核对当前启动产品及选项是否支持板中使用的约束能力。出现 `SPMHDB-212` 并列出 `DFM Advanced checks` 时，当前会话禁用了相应高级制造检查；不能把已保存的 CSet／检查模式或较低的 DRC 数量当作该检查已经运行。此警告本身不是板数据库损坏报告，也不能据它证明其余检查均已通过。

保留设计，核对 Product Choices 中的产品／选项及实际可用许可。Cadence 17.2 本机 `doc/fcoms/fchap.html` 的 File Properties → Tiering 说明：`Update to Tier` 将当前设计能力匹配到当前所选产品与选项；它不是开通高级许可或完成 DFM 验证的操作。该段帮助没有证明具体约束数值会被删除或保留，不应无依据作此承诺。需要降级兼容时，在副本记录操作前后能力、约束和模式并保存重开核验，不只以提示消失作为成功判据。

在可丢弃副本进行有针对性的违规测试：制造一处明确的线宽、间距、允许层或路径偏斜违规，更新相应 DRC，核对实际规则来源、要求值和测得值，然后回退并重新检查。必要时使用端点、连接和长度明确的小校准板。

不要用未布线板的零错误、旧 DRC 标记或只读取存量结果代替当前检查。若内部场求解失败，将几何长度结果、延时／阻抗结果和失败日志分别记录；不能把长度规则或 CSet 数值当作 SI、阻抗或制造认证。

最终分别记录：源规则映射、用户要求的新分组、原生保存重开、完整回载、实际 DRC 作用、全板连接／几何、GUI 和硬件时序的状态。未验证的项目继续保留，具体工程结论只写到对应工程报告。
