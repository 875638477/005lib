# AD 转 OrCAD／Allegro：人工操作教程

本文介绍人工操作顺序，不含脚本、项目副本或某个工程的验收结果。菜单名称依据 Capture 17.2 本机帮助与已记录的转换过程整理；其他版本以现场菜单和帮助为准。文档存在不代表当前电脑的转换器、许可证或界面操作已经验证。

需要了解网络比较、缓存层次和原生审计原理时，参阅[通用转换方法与验收](ad_to_cadence_conversion_workflow.md)。本教程中的所有实际文件均放在用户指定的 `<工程根>`，学习库只保存可复用方法。

专项步骤见[网络名称与端口排版](capture_netlabel_layout_rules.md)及[网表导出与导入排错](capture_allegro_netlist_troubleshooting.md)，包括H镜像后的热点、近端双显归并、名称长度设置和旧输出路径核对。

网表与连接核对后，按[AD规则迁移到Allegro](ad_to_allegro_constraint_migration.md)处理作用域、约束集、差分／匹配组、间距下限与完整配置回载；规则验收单独记录。

## 1. 准备源工程与工作副本

1. 在文件管理器找到完整 AD 项目，确认包含工程文件、全部原理图、PCB 和项目结构文件。保留原件，复制到`<工程根>`内的独立工作目录。
2. 在 AD 打开副本的工程文件，查看工程树和缺失文件提示，逐页打开确认能够读取。记录总页数、多单元器件及版本信息。
3. 按本机版本从 Project 菜单或项目右键执行编译／验证，保存 Messages 中的错误与警告。项目结构文件由 AD 生成，不手工猜写。
4. 按目标转换器要求，把副本原理图另存为兼容的 Advanced Schematic ASCII 格式，保留原扩展名与完整项目结构。已经符合格式时不必反复另存。
5. 记录源项目的网络作用域、跨页端口、电源及不入 PCB／BOM 的设置。如果原理图与源 PCB 本来有差异，先列出，不用转换操作掩盖差异。

目标是可编辑 Capture 原理图时，需要 Translator 生成 DSN。AD 的 OrCad／PCB2 网表导出不能替代这一过程。

## 2. 使用 Capture 转换器并找到 DSN

1. 启动具有相应功能的 Capture，打开 File → Import → Altium Schematic Translator。若没有该入口，检查本机版本、安装组件和许可情况，不另猜菜单。
2. 在项目文件栏选择 AD 工作副本的项目文件；输出目录选择`<工程根>`内全新的转换目录，不覆盖旧结果。
3. 点击 Translate，等操作结束后查看 Viewlog 或 Session Log，保存完整日志。特别检查未支持对象、未找到库、异常退出和未保存设计等信息。
4. 在输出目录查找 DSN，并从 Capture 打开实际文件。核对页面树与页面内容，确认打开的是本次输出。
5. 如果目录只有日志或中间文件而没有 DSN，先处理错误。没有弹窗不代表转换成功，不能把临时文件改成 DSN 扩展名。

若日志提示基础库或安装根不存在，核对软件安装配置并请技术支持修复本次软件环境；不要改动公共库来掩盖问题，也不要把提示文字直接当命令粘贴进命令窗。

## 3. 建立 OPJ 与配套 OLB

转换器已生成 OPJ 时，直接打开并核对其设计引用。只有 DSN 时按以下步骤建立工程：

1. 使用 File → New → Project，在`<工程根>`内指定项目位置，选择本机可用的 PCB／Schematic 类型。
2. 在工程管理器的 Design Resources 中加入本次转换的 DSN。若向导生成了空白设计，先确认文件身份，再让工程明确引用正确 DSN。
3. 保存 OPJ，关闭并重新打开，确认所有页仍在、路径正确。
4. 使用 File → New → Library 建立本工程的 OLB。在工程管理器展开 DSN 下的 Design Cache，选择符号，执行 Edit → Copy；打开目标库后执行 Edit → Paste，并保存 OLB。
5. 按清单覆盖全部缓存符号，核对多单元、物理脚号及显示内容。Design Cache 是已放器件的设计缓存，OLB 是外部库，两者都要维护。

不要把旧通用库直接改名冒充本次配套库。若人工复制不能完整覆盖共享脚、引脚可见性或包装映射，需要技术支持用原生接口审计、导出并读回核对；符号能显示还不够。

## 4. 核对元件值和冲突属性

1. 从原理图器件属性或工程的属性编辑表核对元件值、显示值与 PCB Footprint。对照 AD 的 Comment 和 Value 参数，检查是否出现空值、NA 或乱码。
2. 需要兼容 ASCII 的流程，只规范元件显示／导出值。常见对应为 Ω 改 R、µ／μ 改 u、± 改 +/-、° 改 deg。保存原文与替换原因，确认阻值、容值和单位含义未变。
3. 不把上述替换批量应用到网络名、脚名、脚号或器件型号。元件值不同也不代表封装不同；封装合并不会合并元件型号或数值。
4. 实例、Design Cache 和 OLB 可能各自带有属性覆盖。修好实例后重新导出配套库，并关闭重开核对，防止更新库时恢复成旧值。
5. 只有日志明确表明导入的自定义 Device 属性与包装冲突时，先把其原文保存到追溯属性，再请熟悉缓存层次的人员清理对应自定义属性。不要删除原生内部器件定义或全局清空所有 Device。

如果 AD 界面值正常而转换后丢值，可能是 ASCII 文件中 UTF-8 字段未被正确读取。人工表格不能解释时，需技术支持检查源字段和逐器件对应关系，不能直接把所有缺值统一填成默认值。

## 5. 逐页修正显示与检查缺网

打开 AD 与 Capture 对应页面，按固定顺序检查 **全部页面**，建立“页面、问题位置、源内容、处理、复核状态”清单。每页既看整页，也放大检查密集引脚区。

### 网络文字方向和长网名

1. 对照 AD 每个标签的实际方向，在 Capture 选择文字／标签，使用本机的旋转或属性功能调整。不要为了把字横放而旋转带电气接点的整个 Port 或电源对象。
2. 保留合理的竖排标签；按实际读图方向安排文字。不能仅根据所属导线横竖决定全部标签方向。
3. 检查完整网名是否可读，是否与脚名、脚号、器件本体和相邻网络文字重叠。先调整文字位置、朝向、间距或局部布局，必要时扩大页面。
4. 短引线放不下文字时，不盲目拉长导线。必须调整导线时保持接点在正确网格，检查交叉与邻近引脚，并重新生成网表核对。
5. 在正常阅读缩放和打印预览中再看一遍。小缩放下的文字占位显示不能直接当成真正截断；属性中完整的字串也不能证明页面没有遮挡。

### 漏标签与真正缺连接

1. 逐处对照源 Net Label、Port 和 Power 的名字、位置、显隐及所属导线。同一导线有多个源名称时分别核对，不用目标标签总数代替逐处检查。
2. 源有标签而目标没有时，先确认是缺少可见名称，还是导线／端口本身没有转换。普通注释文字没有电气含义，不能用它冒充网络标签。
3. 补 Net Alias、跨页端口或电源对象时，选择正确类型，并确认真实接点落在原有导线上。Port 的接点不一定在图形原点；不要凭外观认为已经连接。
4. 同名局部标签、跨页端口与电源可能采用不同作用域。补名称后请核对原生源网络与目标 PST 的逐物理脚网络分组，防止误并网或拆网。

### 实心蓝色符号本体

这里指原理图符号的矩形本体，不是 PCB 封装。

1. 先确认编辑范围是项目配套库／缓存及其哪些实例，保存修改前副本。
2. 在符号编辑器选择遮挡脚名的矩形本体，在属性面板查看 Fill Style 与线条属性，选择无填充／轮廓效果。具体选项名按当前版本显示确认。
3. 若不能可靠设置空心矩形，可在保留引脚与定位的前提下，用同一四角坐标的四条 Line 画边框，再去掉遮挡的填充图形。
4. 保存项目库后，按明确范围更新缓存；保留原理图实例属性和位号，更新后检查全部受影响实例。不要为去填充而删除重放器件。

大批量对象、特殊共享脚或缓存保存异常需要原生审计／技术支持处理。只改默认绘图填充不会自动修改所有已存在的符号本体。

## 6. 配置 PCB 项目私有库并建立映射

1. 把该项目需要的 PSM、DRA、PAD 和器件定义放`<工程根>`内的私有库目录，保留来源。PSM 用于放置，DRA 用于编辑，PAD 是焊盘依赖。
2. 从项目专用启动配置进入 Allegro。在本机的 User Preferences Editor 中找到库搜索路径，核对 psmpath、padpath 及需要的 devpath 指向项目私有库。
3. 修改前确认保存位置属于项目配置，避免覆盖用户全局环境；没有私有环境入口时请技术支持建立项目启动方式。设置后重新启动该项目并读回实际路径。
4. 在 Capture 中把 PCB Footprint 映射到实际存在的封装名称，逐项核对脚号和焊盘。名称相似或文件存在不能证明封装正确。
5. 先处理缺库、路径和名称别名，再单列源原理图与 PCB 的真实脚号差异。厂家故意缺脚、机械焊盘、共享逻辑脚和不入 PCB 器件都需要来源依据，不能为了导入通过而补脚或改接。

界面查到一个同名封装还不能排除搜索路径命中了旧公共库。严格导入与原生读回须确认实际使用的定义及引脚对应。

## 7. 合并只有名称或方向不同的封装

0402、0603 等电阻、电容都可能出现大量后缀。后缀只用于筛选候选，不直接决定是否相同。

1. 在封装编辑器打开候选 DRA，统一单位与观察方向；检查脚距、焊盘中心、脚号、外形和固定极性文字。
2. 打开对应 Padstack 检查全部层：铜、阻焊、锡膏、钻孔／槽孔和偏移。丝印、装配边界、机械外形和属性也参与比较。
3. 按允许的角度旋转对齐，核对每个编号焊盘能否完全对应。旋转与镜像分开判断；不能仅因两脚电阻无极性就忽略脚号交换。
4. 确认等价后选定保留名称，记录旧名称、保留名称和角度补偿。保留真实尺寸、脚距或外形不同的组。
5. 在板的副本中使用本机支持的更新／替换机制。若定义方向改变，同步补偿放置角度，确保焊盘的实际位置和网络不变。
6. 替换后逐项核对位号、数值文字、角度和所在层；有些“保留文字”操作仍可能调整位置或遗漏特殊层文字。
7. 同步 Capture 实例、缓存及配套 OLB 的封装引用，重新生成网表，再严格导入板副本。最后关闭、重开，确认主封装名称与实际符号一致。

全层焊盘等价、绝对坐标、已布铜几何和网络是否保持，不能只靠叠图或定义数量判断。批量合并需要原生审计与完整差异报告；没有这些证据时保留候选差异，不把未经核实的封装强行并成一组。

## 8. 生成 PST 并严格导入 Allegro

1. 保存全部页面，在 Capture 工程管理器选中 DSN，使用 Tools → Design Rules Check，检查多单元位号、物理脚号、跨页连接、电源和未连接问题，保存报告。
2. 使用 **Tools → Create Netlist → PCB 页签 → 右侧 Setup**，将 **Device/Net/Pin name char limit** 设为 **255**，确认返回。部分版本将页签称为 PCB Editor；这是 Capture 的网表生成设置。官方默认 31，长转换标识被截断可引发后续多单元包装失败，不能一开始就把它判为封装实体错误。
3. 核对 Part Value、PCB Footprint 属性映射、实际配置文件和`<工程根>`内独立输出目录，再生成网表。打开本次新日志，确认 **0 errors、0 warnings**；同时确认 **pstchip.dat、pstxprt.dat、pstxnet.dat** 三份均为本次生成、非空且完整，不能仅凭文件存在就宣布成功。若有警告，先逐条查明。
4. 保存工程，重开 Setup 确认仍为 255；换目录、换工程或复制 DSN 后重新确认。DSN 不保证携带菜单设置，独立导出器成功也不代表当前 GUI 已采用相同值。必要时请原生审计逐物理脚核对这套 PST 与已保存原理图的网络分组和网名。
5. 在 Allegro 打开现有板的工作副本，通过 File → Import → Logic 的本机对应入口，选择 Capture／PCB Editor 网表和上述目录。Capture 生成成功尚不代表已经执行这一步。
6. 保持严格检查，不用允许自动拆除已有走线、忽略固定对象或跳过脚号问题的设置来消除错误。查看完整导入报告，先修复实际缺库、缺封装、位号和脚号问题，再重试新副本。
7. 导入成功后保存为新版本，关闭并重新打开，核对器件数量、封装名、脚号、网络、位置和已有走线；重新查看未连接和 DRC 状态。

三份 PST 出现、窗口显示完成或没有错误弹窗，都不能单独证明电气等价。需由原生审计确认源编译结果与最终 PST 的完整物理引脚网络分组，并读取最终板复核。生成网表可能更新设计的包装元数据，因此检查以最终交付文件为准。

导入通过与布线完成分开记录。局部 DRC、旧标记数量或存量零错误不能替代当前整板 DRC；视觉检查也不能替代真实铜连接检查。

即使 netrev 报告零错误、使用关闭 DRC 的选项且 Unrouted 总数不变，保存期间仍可能自动重算动态铜，使原本接地的引脚脱离铜连接。带 NO_RAT 等抑制飞线属性的网络，不能靠未布线数量发现这种变化。导入前后及保存重开后，应逐物理脚比较实际铜连通分区；几何包围框、摘要哈希和逻辑网表都不能单独代替这项检查。禁用动态填充后再恢复的操作也须在独立副本验证，不能当作未经验证的通用保护步骤。

## 9. 打包工程并在新目录重开

1. 保存工程，关闭其原理图页面，激活正确项目，使用 File → Archive Project。
2. 按需要勾选 Library files、Output files 和 Referenced projects，选择`<工程根>`内的归档目录；需要单文件归档时使用对话框的单文件选项。
3. 用 Add more files 加入未自动收录的 PCB、私有库、环境配置、转换记录和必要报告。额外文件被加入归档并不代表 OPJ 已自动引用它们，仍要核对工程和启动路径。
4. 在新目录解压，打开 OPJ 与板，检查 DSN、OLB、PSM、PAD 等实际引用以及私有库搜索路径，确认不依赖原工作目录。
5. 保存简短中文说明：打开哪个工程、私有库在哪、当前版本、已验证内容和仍待处理的问题。归档文件不重复混入完整历史候选版本。

只在同一电脑换目录打开，应记为“重定位检查”，不能写成“另一台电脑验证”。菜单归档也不证明 PCB、布线或制造已经验收。

## 10. 清理可重新生成的中间物

先完成新目录重开、依赖检查与最终文件身份记录，再清理。所有清理范围都在`<工程根>`内按明确清单逐项确定。

| 内容 | 处理方法 |
| --- | --- |
| 自动生成的临时 XML、重复预览、重复提取表和可重跑的中间输出 | 确认有源文件、对应软件版本和生成方法，且不再是待处理问题的唯一证据后移除 |
| 同内容工程副本和重复库副本 | 比较身份并确认当前引用，再移除冗余副本；不要只按文件名判断 |
| 自动备份、锁文件和会话文件 | 先确认软件已关闭、没有未保存操作且文件不被活动会话使用，再按项目清单处理 |
| 原始输入、最终工程与依赖、唯一可编辑源库、最终转换记录和关键验收证据 | 保留；不能因某种扩展名常是临时文件就整类删除 |
| OPJ 工程、正在使用的 CFG 网表配置、配套 OLB 与项目启动配置 | 保留；不是垃圾文件，不能按扩展名递归删除 |
| 仍用于解释缺网、映射或合并问题的失败日志 | 保留必要证据；问题关闭后可精简重复过程，不能把失败历史改写成通过 |

PST 可以重新生成，但当前交付使用的那一套应保留；DRA 是可编辑封装源，不因为已有 PSM 就删除。中断或异常关机后先确认保存状态，零字节／截断日志不能当成功依据。

运行清理工具前，先以文本方式检查其删除范围。明确排除 OPJ、当前 CFG、DSN、OLB、BRD 以及唯一可编辑库源；仅保留 DSN 无法保证工程组织、库引用和 Create Netlist 菜单设置完整。清理后重开工程并重新核对 Setup 的 255 与实际配置路径。

清理后再检查项目树、库路径和启动入口，保存清理清单与剩余问题。学习库只回写通用操作方法，不复制本次项目、中间物或大型运行记录回来。

## 11. 人工检查与原生审计如何配合

| 人工可以确认 | 仍需原生审计或专业检查 |
| --- | --- |
| 页面齐全、网名完整、文字方向与遮挡、空心本体效果 | 每个物理引脚无缺失、拆网或误并网，局部／跨页作用域一致 |
| 元件值和封装名称看起来正确 | 实例、缓存、配套库及 PST 包装结果一致 |
| 两个封装旋转后外观相近 | 全层焊盘、钻孔、属性、脚号映射与真实绝对几何等价 |
| 网表界面完成、器件在板上出现 | 严格导入日志、最终板脚号网络、已有铜连接与放置保持 |
| 新目录能打开项目 | 依赖完整、引用确实来自交付目录，未借用旧公共库 |

按实际证据分别记“已操作”“已重开”“已电气核对”“已视觉检查”“整板 DRC 已完成”。没有完成的项目保留待办，不能由其中一项推断其他项目也通过。

密集页进一步检查[文字几何与可读性](capture_text_geometry_and_readability.md)：位号和Value应清楚对应本体，不能仅因文字没有交叠就把器件值放到远处。需要程序定位时区分实际可见针文字和隐藏针号、DP与Alias的不同文字锚点，并把离线模型与Capture实际显示分别记录。

换用导出的OLB后，按[缓存来源身份与实际复用](capture_cache_reuse_and_origin_rebase_xml.md)做受控检查：缓存内容相同仍可能因旧来源路径出现重复包。移动工程、改库名或重新放置器件后要重新核查来源、实际缓存数量与连接，不能只看新库已出现在工程树中。


自建库优先的转换见[共享模板流程](capture_user_library_first_templates.md)：先核真实材料／脚号，再共用图形，原生核有效继承及PST缓存脚名；短针距、H镜像热点和来源身份分别留证。另见[实例引脚覆盖限制](capture_generic_symbol_pin_override_limits.md)。
