# 优先复用自己的 Capture 库并统一模板

本方法先确定用户维护的符号库，再统一转换工程中的同类外观。原库只读，记录文件 SHA；原生导出和试放都使用独立快照。工程 XML、分类表、例外坐标、计划和验收结果放 `<工程根>`，学习库只留参数化工具与方法。

配合[缓存、网格和文字清理](capture_cache_grid_text_cleanup.md)、[来源身份与缓存复用](capture_cache_reuse_and_origin_rebase_xml.md)、[实例引脚覆盖的实际限制](capture_generic_symbol_pin_override_limits.md)使用。

## 先按器件功能和材料选模板

从源 AD 符号、当前值、型号、BOM、原厂材料资料和实际脚号建立逐器件分类。位号前缀、封装外形、库文件名或某个空白属性都不能单独决定类型。源符号与显式说明一致、型号字段却矛盾时，记录冲突；按已经确认的依据选择视觉模板，保留原型号、值、封装和位号，不能顺手更换物料。

电容的陶瓷、钽和铝电解／固态电解分别选择合适画法。极性与物理脚号必须可追溯；不能凭一个弧板符号或库名判断材料。未在当前工程识别到某种材料时，可以在派生库预留模板，不向 Design Cache 凭空增加器件。

IC、晶体管和稳压器即使都用三脚封装，也不能直接继承同一模板的功能名称、脚号、电气类型或隐式 Global 标志。先核原有完整物理映射，再借用图形。晶振可以统一母图风格，但双脚、带外壳地脚和额外接地焊盘的真实脚数差异要保留为明确的 schema 变体，不能为了“一种外观”删脚、加脚或把被动脚改成隐式电源。

## 共享的是模板，不是每个位号一份缓存

同类模板按实际物理脚号对齐。先统计所有源 start/hot、针距、方向和脚数，再核用户模板的有序 `PhysicalPart/PinNumber`、局部图形和边框。

- 针距一致时，枚举经过本机验证的旋转／镜像，逐物理脚号求实例姿态和原点，使实际 hot 完全重合。
- 针距不同但本体能放下时，优先统一整类 pin 长度，保持用户本体图形和全部原实际热点；只生成按真实几何条件必要的少量变体，不能按位号复制。
- 个别短针距不能精确匹配时，先给出明确例外计划。若端点确为自由 pin 端，可在网格上对称调整 pin 与原导线端，更新派生 WireBBox；不得触及其他 pin、Alias、junction 或异网。变换前后的完整连接图及 PST 必须再验。
- IC 新增桥接线时，保留旧导线子树，逐段证明不碰异网或未结点交叉；新线必须在既定网格内，并有独立原生连接验证。

普通器件图形也不能假定 `world=O+RM(local)`。使用每个实例原生三个基点得到的 A/B；若新姿态依赖边框 offset，还要原生校准新边框。DP 锚点在已核路径中是 `O+local`，原点变更后只补偿偏移，不随本体再次旋转。见[原生仿射与旧零姿态工具限制](capture_cache_reuse_and_origin_rebase_xml.md)。

## 只借必要图形，保留当前电气与显示

用户库的 PSpice 模型、额外默认属性、默认封装、默认字体及 Global 标志不应无条件带入。保留当前实例完整 Reference、Value、型号、PCB Footprint、原有属性、NC、共享脚和物理脚号映射。借用图形后，需要按物理脚号重新绑定 `position`，不能把 XML 子节点次序当作脚号。

已有显式 DP 的绝对锚点、字体、字号、旋转、对齐与显示模式应逐项保存。保留实例引脚 Name 属性／提示信息，不等于画布仍显示功能名；必须分别读取 Name 与 Number 的实际显示模式。若 Name 隐藏而 Number 显示，应如实记录，不能以有效 Name 值代替可见性证据。静态 `CommentText` 中烘焙的数字不受 Pin Number Visible 控制；源图原本隐藏脚号时，应把这些数字列入明确处理策略，不能以为关闭 pin 显示就能隐藏它们。模板本身保留一套适合未来放置的 Ref/Value 默认显示，当前实例则要求显式 DP 完整覆盖。

## 原始库属性不等于实例有效继承

`PackageUserProp` 在 XML 中存在，不能证明 `GetEffectivePropStringValue` 对当前实例有定义。物化默认值前，必须读取同一保存版本的原生查询，保存 `read_failed/state_code/value/error`，并绑定 XML 与表文件 SHA。

有定义的空字符串是一个真实值；读取失败没有可用值。不得把失败变为空串，也不得把原始 Package 属性提升成显式实例属性。只有明确复核过的“原生未定义”结果可以作为不物化的例外，其失败状态仍需在保存重开后保持；其他失败阻止自动处理。没有显式覆盖、原作用域又有多个候选值时，以原生有效值为依据，不能按 XML 顺序猜优先级。

[共享双端模板生成器](../scripts/capture_xml_tools/build_shared_visual_templates.py)要求 `--effective-binding`。该绑定使用 `CAPTURE_NATIVE_EFFECTIVE_PROPERTY_BINDING_V1`，包含 `source_xml_sha256`、各原生表的 path/SHA，以及逐实例／属性、带依据的 `reviewed_undefined_results`；不接受全局“所有失败都算不存在”。

## PST 的顺序和名字必须提前预测

实例 Name 覆盖可能只影响显示，PST 仍使用固定缓存脚名。不要修改实例 Number 来追求共用模板，也不要因为某 setter 返回成功就认为 Type 已生效；需要隔离保存重开小样和真实 PST 证据。

在最终候选 XML 确定后、PST 导出前，用[声明计划生成器](../scripts/generate_pst_pin_declaration_plan.py)读取原源 XML、最终候选和明确的模板分类 trace。按 `PhysicalPart.PinNumber.position` 数值排序；名称来自 active `SymbolPinScalar`，不取实例 Name 覆盖。只为实际复用模板且声明确有变化的物理位号生成 before/after。工具不读取 PST 差异，不能反向据失败结果扩大白名单。

先保留原始严格 PST 比较结果，再用[有界声明比较器](../scripts/compare_pst_parts_bounded.py)检查预置计划。它仍要求每个物理脚号的完整电气 payload、section 和 primitive body 精确一致；其他位号不放宽。网络分区、每脚网名、缺失／重复 pin 与 PCB 导入是另外的门禁。

## 网络文字同步整理

全工程按真实导线方向和热点审查跨页符号，成组统一已验证的 H 镜像与文字对齐策略。镜像可能因包络而移动热点，应读回绝对 hot 并补偿原点；不要为修朝向挪导线。Name 的位置按实际字符串和 GDI 字形计算，同列标签保持可读间距。

Port 与 Alias 的归并需要名称逐字一致、实际 net 一致及真实连续 wire 路径，不能跨未结点交叉。保留清楚的可见标识，异名连接标签不合并。详见[网络名称与端口布局](capture_netlabel_layout_rules.md)与[真实文字几何](capture_text_geometry_and_readability.md)。

## 工具输入与验收边界

[双端模板工具](../scripts/capture_xml_tools/build_shared_visual_templates.py)显式接收 input、reference XML／native frames、八姿态校准、原生 effective 绑定、材料计划、模板配置和独立 output。[晶振母图工具](../scripts/capture_xml_tools/build_crystal_visual_family.py)显式接收原库 XML、schema 配置和同版本 native pins；当前实现只处理已审查的单 NormalView、被动且无隐式 Global 的晶振 schema；保留源脚数及完整 pin 子树，只借母图，其他语义停止自动处理。两者均不启动 CAD、不写 DSN/OLB，也不自动覆盖现有输出。

每阶段保存配置、库图形来源、属性物化与未定义保留表、每脚映射、坐标例外、完整变换白名单和逆变换证明。代数自证只是离线门禁；最终仍需原生保存、独立重开、完整有效属性查询、实际 pin/frame/DP、PST、网格及整页文字检查。图形改了就重新生成逐页预览；模型预览不等于 GUI 像素验收。

最后导出匹配当前缓存的工程私有 OLB，核库级字体／默认值，并统一 DSN 的实际 source identity。从准确库做不保存试放，确认缓存数量不再增加。原用户库、源 AD 和封存基线应有独立 SHA 保护记录。派生工程库不同于原用户库，不应宣称从任意旧库放置都一定复用现有缓存。

## 显式引脚显示与外围框的最小适配

在保存重开后的官方 DSN→XML 中，先检查 placed `PortInstDisplayProp`／`PinDisplayProp`。若某个脚的名称或脚号已有显式显示位置、字体、旋转和显示类型，渲染时应优先使用这套记录，不能继续套默认脚号偏移。默认预览算法可能遗漏显式覆盖，因而产生“文字压在本体上”的模型假阳性。AUTO 对齐尚未由 GUI 校准时，可枚举合理的水平／垂直锚点及两种旋转方向，形成有界字形包络；只有所有适用变体都与保留对象分离，才能关闭这一有界模型疑点，不能把 AUTO 默认为 LEFT。

原生显示属性迭代器返回空，不足以证明官方 XML 中没有显式 PinDP。保留探针的对象类型、返回码、空结果和失败；若探针约定必须读到指定条目，结果为空应明确 FAIL，不能制造锚点或改用猜测坐标后称原生实测。官方保存重开 XML 可作为另一项结构证据，但必须绑定 DSN／XML 的 SHA，并说明它与直接 SDK 读取的区别。详见[实例引脚覆盖与接口限制](capture_generic_symbol_pin_override_limits.md)。

若真实用户外观要求允许小幅适配，而文字只碰到冗余外围矩形，可提出“只删外围四条 Line”的窄白名单：精确记录四个完整图元子树，保留内层图形、Caption、SymbolBBox、所有 pin、PhysicalPart 与 DP。不能把真正封装轮廓或功能图元误当冗余边框。删线后仍需原生保存重开，核真实仿射框架、实际 pin start/hot 和显示锚点；库边框的重新计算可能影响旋转／镜像实例，离线代数相等不能替代此门禁。

在上述其余图形／字形和实际坐标均不变已证的前提下，只删除非电气笔画是场景集合的缩小：它可消除与这些笔画的相交，不能新增或扩大其它对象的相交。这是有明确前提的单调性证明，仍应生成最终逐页模型预览，并重新导出派生 OLB、核对 Cache/OLB 内容及不保存的放置复用。旧版试放只证明旧版库，不可直接冒充改图后的试放。始终保留“离线字形模型”和“Capture GUI 像素验收”的边界。
## 原生任务的临时目录尽量短且使用ASCII

原生导入的前半段成功，不足以证明保存后独立重开也成功。若相同输入在较长工作路径下启动或readback异常，可用独立、简短、ASCII名称的工作根目录作对照，保持软件版本、输入哈希、参数、库环境及完整流程相同。每阶段仍检查进程退出码、输出完成标志、输入保护SHA和实际读回报告，不能只看BRD文件存在或netrev日志。

短目录下通过，只支持“本次可能与路径兼容相关”的经验推断，不证明官方存在某个固定字符限长，也不能擅自把所有路径故障归因于中文。保留异常退出的原始记录和完整失败快照；需要减小体积时，可逐成员CRC/SHA验证后无损压缩，附原路径还原清单，不能把失败报告改成PASS。

完成对照后，对正式发布路径的DSN、派生OLB、PST、PCB和元数据重新绑定SHA；临时板只能在所有必需门禁闭合后发布。大型原生转储归档也应保持相对目录和每文件SHA，解压还原后复核，原CFX/规则失败及有界说明分别保留。实际GUI截图只证明所示版本、页面和对象范围，旧校准截图不能冒充后来改图版本的整工程像素验收。
