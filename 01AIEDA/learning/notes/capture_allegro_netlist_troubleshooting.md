# Capture 到 Allegro 的网表导出与导入排错

本文为可复用的纯操作方法，不含项目位号、固定路径、实际结果或代码。所有诊断输入、副本、输出和记录保存到 `<工程根>`。菜单以本机版本与官方帮助为准；每个工程都须核对其当前设置。

相关入口：[人工转换教程](ad_to_cadence_gui_workflow.md)、[通用方法与验收](ad_to_cadence_conversion_workflow.md)、[网络文字排版](capture_netlabel_layout_rules.md)。

## 1. 先确定失败发生在哪一步

将问题分为 Capture 原理图保存、PST 包装导出、Allegro 逻辑导入和最终板网络核对。先看最早出现的错误及其前面的警告，不把后续所有报错都当成封装实体损坏。

三份 PST 已出现也可能只是失败过程中留下的部分输出。需同时检查完整网表日志、任务结果和物理器件包装，不能仅凭文件存在或没有弹窗就继续导入。

| 现象 | 首先检查 |
| --- | --- |
| 名称截断警告，随后多单元包装失败 | 名称长度限制与截断后的器件标识，不先改脚号或重建封装 |
| 找不到封装／焊盘文件 | 本次实际使用的私有库路径、文件及依赖 |
| 缺脚、多脚或旧位号要求 | 是否导入了旧 PST，源原理图与 PCB 是否存在真实差异 |
| 选择了新目录仍像旧结果 | 对话框保留路径、旧缓存输出、公共快捷脚本和当前板身份 |

## 2. 名称长度限制可能触发多单元包装失败

转换后的器件标识可能较长。Capture 网表的名称上限过短时会截断组件、网络或引脚名称，破坏原有标识关系，并可能引发后续多单元包装错误。

出现 ORCAP-36006 一类截断警告，随后又有 SPCODD 包装错误或 ORCAP-36026 时，应先核对长度设置。这组现象提示检查方向，不代表这些错误永远只有一种原因。

在 Capture 17.2 中按以下路径操作：

1. 保存全部页面与工程，在工程树中选中本次要导出的 DSN，确认不是同名旧设计。
2. 进入 **Tools → Create Netlist**，选择 **PCB** 页签。某些版本／帮助将这一页称为 PCB Editor，以本机实际显示为准。
3. 点击该页右侧的 **Setup**，找到 **Device/Net/Pin name char limit**。
4. 该字段官方默认值为 **31**，Capture 允许的最大值为 **255**。需要保留长标识、且下游工具支持时输入 **255**，确认并返回 Create Netlist。
5. 核对配置文件及输出目录，使用 `<工程根>` 内本次专用的新目录，再执行生成。不要把 Allegro 的 PCB 导入设置当作这里的 Setup。
6. 打开本次新生成的完整网表日志，确认结束摘要为 **0 errors、0 warnings**，并且没有名称截断、多单元包装失败等信息。若仍有警告，逐条查明并记录；不要只隐藏消息或沿用旧日志。
7. 确认同一输出目录中的 **pstchip.dat、pstxprt.dat、pstxnet.dat** 均为本次生成、非空且完整。这三份文件必须成套使用；文件出现本身不代表生成成功。
8. 保存工程，重新打开 Setup 确认仍为 255。关闭重开工程后再次核对；复制 DSN、换工程或换电脑后也重新检查。最后核对导出连接与已保存原理图，必要时由原生审计逐物理脚比较网络分组及网名。

到这里确认的是 **Capture 网表生成**。随后还要在 Allegro 指定这套 PST 的实际目录并严格导入，检查导入日志和最终板网络；生成成功不能写成 PCB 已导入或整板已验收。

为确认根因，可在同一份已保存 DSN 的独立快照上仅改变长度设置作对照。不要同时改型号、封装名、脚号和连接，否则无法解释是什么解决了问题。

上述长度设置不等于放宽所有类型名称的全部限制。符号库、旧版接口或下游板的限制仍按各自帮助核对。若 Allegro 新建板提示 Name Too Long，再检查本机 Setup → Design Parameters → Design 下的 Long Name Size；不能未经核对就重建已有板。

## 3. 工程设置与全局设置分开确认

Options → Preferences → More Preferences → Netlist 中的 **Apply Allegro Character Limits on All Projects** 控制是否把字符限制应用到所有项目。它是全局应用开关，不是长度输入框。

只修当前工程时，先明确该开关状态，在当前项目的 **Create Netlist → PCB 页签 → Setup** 设置长度并保存工程，再关闭重开对话框确认实际值。复制一份 DSN 只复制设计数据库，不能据此认定 Create Netlist 菜单设置也已复制；即使这份 DSN 以前由独立工具按 255 成功导出，当前 GUI 仍可能显示 31。

**OPJ 与 CFG 不属于可按扩展名批量删除的垃圾文件。** OPJ 保存工程组织和引用；网表配置 CFG 用于当前导出映射。连同实际配套 OLB、私有库和项目启动配置一起保留，打包后从新目录重开核对。保留这些文件也不免除重新检查 Setup 数字值。

使用清理工具前先以文本方式查看删除范围，明确排除 OPJ、当前使用的 CFG、DSN、OLB、BRD 及唯一可编辑库源。递归按扩展名删除工程或配置会丢失引用／设置；应改为只清理已确认可重生的中间物，并保留清理清单。

不要猜写隐藏工程字段、覆盖全局配置或把全局开关当成长度值。运行中的 Capture 可能缓存配置，外部改写配置不等于当前界面立即生效；最终以本机重新打开后的实际值和本次新日志为准。

官方依据为 Capture 帮助中的 Setup 对话框、Extended Preferences 对话框及相关版本说明。可从当前对话框的 Help 查找，注意区分当前版本与旧版教程。

## 4. 排除旧网表目录与导入缓存

Allegro 导入对话框可能保留上一次的路径。某些公共快捷脚本只执行 Import 动作，没有重新指定网表目录，因此可能继续读原理图目录下较早的输出。

1. 在 Capture 生成成功后记下实际输出目录，核对最新日志与 PST 身份，不混用不同批次的三份文件。
2. 在 Allegro 的 File → Import → Logic 中明确浏览到这一目录，确认实际读取位置后再导入。
3. 若仍报旧脚号、旧封装或旧器件要求，先检查被读取的 PST 内容和输入板身份，不立即回头重改已修复的设计。
4. 重试使用全新输出目录或按清单整理旧输出；保留必要日志与输入身份，避免新旧文件混放造成误判。

存在已完成映射的新工程时，旧原理图输出目录不会自动随之更新。更新启动入口、OPJ 引用和当前网表路径后，还要以实际导入日志证明读取的是新结果。

## 5. 库搜索路径与自包含交付

将当前项目所需 PSM、DRA、PAD、器件定义及环境配置保存在工程私有库中，从项目专用入口启动并核对实际搜索路径。不要依靠修改公共库来解决一个项目的路径或别名问题。

板文件可能已缓存所用封装，因此在某个公共库环境下导入成功，并不自动证明工程可独立迁移。自包含交付还应保留可编辑库源、依赖和可重建的私有配置，并在新目录重开检查。

反过来，公共库路径出现在日志中也不能单独证明本次错误就是库损坏。先核对读取的 PST、板内已有定义和真实引脚映射，再决定是否需要补库或改封装。

## 6. 独立 DSN 快照导出器的作用

当 GUI 设置不易确认或需要稳定复现时，可由技术支持提供独立导出器。它应按以下步骤工作，无需在教程中粘贴命令或脚本：

1. 接受源 DSN、输出根、项目配置和 Cadence 安装根等明确参数。
2. 确认源设计已保存，建立新快照并记录来源身份。
3. 对快照运行官方网表导出工具，明确指定本次名称限制和配置。
4. 每次使用新的输出目录，保存完整日志、实际参数、结果和当前输出身份；只有通过检查的目录才作为最新有效输出。
5. 不修改用户唯一原件、全局 Capture 设置或系统执行策略。

需要快照是因为原生 PST 包装可能更新 DSN 的内部元数据。导出器处理磁盘中已保存的内容，不能自动包含 Capture 窗口里尚未保存的编辑。

独立导出成功不代表 GUI 默认值已经保存为相同设置，也不代替页面视觉检查。需要从 GUI 再导出时，仍须打开 Setup 核对实际值。

## 7. 用最新板副本做严格导入

1. 保存当前 PCB，并从最新已保存文件建立独立副本。确认不是较早备份，也不把未保存窗口内容误当成快照输入。
2. 选择本次成功的同一套 PST，保留严格检查；不使用自动拆除已有走线、忽略固定对象或跳过引脚问题的设置来换取通过。
3. 保存完整导入报告，检查器件、封装、脚号与网络要求。若失败，回到最早错误定位具体层次。
4. 成功后另存新板，关闭并独立重开，核对器件和焊盘、放置、网络、已有走线及物理铜连接；需要时使用原生审计逐项比较。
5. 对最终原理图／PST 做完整物理引脚网络分组比较，既检查漏脚、拆网和误并网，也检查每脚网名是否发生意外变化。

导入成功、原有几何保持、逻辑网络等价、实际铜连通和整板 DRC 是不同的验收层次。分别记录，未完成的布线、DRC 或 GUI 检查继续保留待办。

netrev 零错误、关闭 DRC 的选项和 Unrouted 总数不变，仍不能排除保存时动态铜自动重算造成的断接。NO_RAT 等属性可能令接地引脚脱铜后仍不增加飞线统计。必须在导入前后及保存重开后，逐物理脚比较真实铜连通分区；不能只看几何包围框、哈希或逻辑网表。任何临时禁止动态填充再恢复的流程，都应先在可丢弃副本验证实际连接保持。

Value 规范化后若严格 PCB 几何比较仅发现器件值文本和包围框变化，按 [Value 文本的真实 owner 与有界几何验收](rc_value_display_conventions.md#pcb-value-text-owner-audit) 逐对象核对；保留原严格 FAIL，不全局忽略 text/bBox。配套只读 SKILL 定义位于该方法链接中。
