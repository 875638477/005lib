# WiGig Key 1-DP 主机接口与 Capture 连接验证方法

本笔记保存可复用的接口核查、供电预算和原生网表验证方法。具体工程的端口分配、元件位号、设计副本、失败证据、校验数字及最终文件路径保存在对应工程目录。

## 1. 先确定模块和接口版本

先核对模块标签、完整订货号、RF 天线模块及扩展坞型号，再查相应原厂资料。M.2 的机械 Key、75 个位置编号、实际接触片数、模块观察方向和主板观察方向必须分别确认，不能用普通 Wi-Fi Key A/E 图代替 Key 1-DP。

Intel 18260NGW 的原厂简介明确列出 Key 1-DP、两路 PCIe、USB 和 DP；它使用独立的 WiGig 射频天线模块。18260 与 18265 是不同产品，不能把另一型号的针脚、RF 模块、功耗、驱动或固件要求直接套用。原厂资料没有给出的完整模块峰值电流、上电细节或特定主板兼容性，应保留为待确认项。[Intel 18260 产品简介，文档 332933-002EN，第 2 页](https://www.intel.com/content/dam/www/public/us/en/documents/product-briefs/tri-band-wireless-ac-wigig-18260-product-brief.pdf)、[Intel 对不同组合模块的识别说明](https://www.intel.com/content/www/us/en/support/articles/000024989/wireless.html)

标准参考使用 PCI-SIG 原作文档。以下公开链接是文档镜像站，不是 PCI-SIG 官方发布站；引用时保留作者、版本、日期和印刷页码。取得正式资料时仍应核对当前标准、勘误以及模块厂商约定。

- [PCI-SIG 官方 M.2 1.1 资料入口](https://pcisig.com/PCIExpress/Specs/M.2/_1.1)：部分下载需要会员权限。
- [PCI Express M.2 Specification Rev. 1.0，2013-11-01，原作文档镜像](https://myriad.splitkb.com/assets/pdf/m2_spec.pdf)：模块侧 Table 23，印刷第 113 页；平台侧 Table 44，印刷第 148 页。
- [PCI Express M.2 Specification Rev. 1.1，2016-03-07，原作文档镜像](https://attychen.github.io/Download/circuit-design/%E8%AE%BE%E8%AE%A1%E8%A7%84%E8%8C%83/%E5%90%84%E7%B1%BB%E9%80%9A%E4%BF%A1%E4%B8%8E%E6%8E%A5%E5%8F%A3%E5%8D%8F%E8%AE%AE%E6%A0%87%E5%87%86/PCI_Express_M.2_Specification_Rev1.1.pdf)：平台侧 Table 49，印刷第 174 页。下文页码均为印刷页码，PDF 阅读器的页面序号可能不同。

## 2. 分开分配两路 PCIe x1

Key 1-DP 的两套 PCIe 信号应按两个独立 x1 接口核查。Wi-Fi 通常使用接口 0，WiGig 使用接口 1；是否允许共享或其他分配由模块厂商确认。两条 Lane 不应直接当作一个 x2 设备配置。每路都要分配可用 Root Port、REFCLK、CLKREQ#、PERST#，并核对 HSIO 复用与固件映射。

下表是**平台侧**方向，依据 Rev. 1.1 Table 49，第 174 页。模块侧资料的 PET/PER 名称可能与平台侧相反，应逐方向判断。

| 平台侧信号 | 接口 0 引脚 | 接口 1 引脚 |
|---|---|---|
| 主机 TX P / N，送模块 RX | 35 / 37 | 59 / 61 |
| 主机 RX P / N，接模块 TX | 41 / 43 | 65 / 67 |
| REFCLK P / N | 47 / 49 | 71 / 73 |
| PERST# | 52 | 66 |
| CLKREQ# | 53 | 68 |
| PEWAKE# | 55 | 70 |

USB 2.0 的 D+ / D- 为 3 / 5，通常用于蓝牙。3.3 V 电源触点是 2、4、72、74；地触点包括 1、7、18、23、24、29、30、33、36、39、45、51、57、63、69、75。不能因为已有屏蔽壳接地而遗漏信号地触点。该旧版 Key 1-DP 的 64 脚是 Reserved，不应照其他版本图误接 1.8 V。

## 3. 耦合电容、时钟和复位

PCIe 交流耦合电容放在发送端路径，每根 TX 线各一个；主板 TX 与模块 TX 分别属于不同发送端，不能在主板 RX 侧盲目再串一次。先检查已有芯片、模块及主板路径的电容，避免重复耦合。

Rev. 1.1 §6.8、Table 75，第 231 页给出的 PCIe 电容范围为 Gen1/2 的 75–265 nF、Gen3 的 176–265 nF。220 nF、±10% 的标称选择落在这些范围内；实际仍需按目标代际、芯片指南、介质偏压效应及布线要求核查。§6.8 为信息性总结，最终以对应 PCIe 规范和器件要求为准。

REFCLK 与对应 CLKREQ# 的硬件、Root Port 和固件映射必须一致。不要把两路请求线随意并联，也不要只根据网络名称推断 PCH 时钟/GPIO 电平。需要核对 GPIO 电源域、strap、复用、输出模式及 ASPM/时钟门控设置。

两路 PERST# 可以在厂商允许时共享平台复位来源，但串联 0R 不会产生延时。Rev. 1.1 §3.1.4、Table 17，第 110–112 页要求按设备启动条件选择电源稳定到复位释放的时间，并规定 REFCLK 在释放前的稳定时间。应在模块供电点测量时序，不能把全板 PLTRST# 有波形当作模块时序已经合格。

## 4. 边带电平、无线禁用和可选接口

CLKREQ#、PEWAKE# 按 3.3 V 开漏/线与接口处理，平台上拉电阻应满足相应标准范围。Rev. 1.1 §4.1、Table 40，第 163 页规定主机侧 CLKREQ#/PEWAKE# 上拉为 9–60 kΩ；10 kΩ 是可审查的常见起点，仍需计算并联电阻、漏电、低电平灌电流和待机电源状态。

54 脚 W_DISABLE2# 通常控制蓝牙，56 脚 W_DISABLE1# 通常控制 Wi-Fi/WiGig，均为低有效；18260 原厂简介确认一套硬件控制由 Wi-Fi/WiGig 共用、另一套用于蓝牙。默认启用、平台硬件禁用、开机/待机状态均应明确设计。模块内部上拉的要求不能直接代替主机 GPIO、电源时序和掉电反灌核查。

SUSCLK 在 50 脚，为 3.3 V 的 32.768 kHz 信号；若模块需要其低功耗功能，应检查精度、占空比和所需电源状态。LED 输出通常可选。NFC I2C/ALERT 和 COEX 不是 PCIe 工作的必接项；未使用时按模块要求留空。特别是 Rev. 1.1 的 NFC/COEX 相关接口采用 1.8 V 定义，不能从 Rev. 1.0 的旧图抄来 3.3 V 上拉。

## 5. WAKE# 必须同时计算外部上拉与深睡下拉

多个开漏 WAKE# 可在电平、电源状态和平台许可均满足时线与；先确认每一个参与设备确为开漏，且掉电时不钳位。改变共享上拉会影响共享线上所有设备。

部分 Intel PCH 的 WAKE# 在 Deep Sx 中可能启用内部下拉。Intel 600 Series PCH 的公开资料列出 15–40 kΩ 可配置下拉，并要求查看 DSX_CFG。外部上拉满足 M.2 的电阻范围，并不自动保证下拉启用时高电平有效。[Intel PCH Integrated Pull-Ups and Pull-Downs](https://edc.intel.com/content/www/us/en/design/ipla/software-development-platforms/client/platforms/alder-lake-desktop/intel-600-series-chipset-family-platform-controller-hub-pch-datasheet-volume/005/integrated-pull-ups-and-pull-downs_10/)

计算示例：3.3 V、10 kΩ 上拉与 15 kΩ 下拉形成分压，空闲高电平约为 `3.3 × 15 / (10 + 15) = 1.98 V`，还没有计入供电误差及漏电。应与实际接收器 VIH 比较，不能宣称唤醒已通过。

可审查的处理方式包括：固件明确关闭相关 Deep Sx 内部下拉/相应深睡模式，或另行设计满足电平及掉电隔离要求的接口电路。不能无依据加缓冲，也不能只在说明里写“支持唤醒”。交付时应记录固件依赖、实际配置和各目标电源状态的测量结果。

## 6. 3.3 V 供电要有真实 BOM 额定值

把四个电源触点接到经过预算的同一电源域，并核查每个必需地触点。标准的 Key A 供电能力表不是特定模块的实测峰值或整板余量。模块、外接 RF 部分、同轨其他负载、启动浪涌、线路压降、温升和保护方式均需单独预算。缺少模块峰值电流资料时，明确保留未签核项。

供电路径上的 0R 必须有确定厂商料号、最大电阻、允许电流及降额条件；封装名字或 `0R/1206/1%` 显示格式不能证明它能通过数安培。对 jumper 应按最大电阻和实际额定电流验收，不能把普通非零电阻精度当作 jumper 的导通指标。举例：Vishay D/CRCW 资料的 CRCW1206 jumper 表列 3.5 A 和最大 20 mΩ，但这不是所有 1206 的通用额定值，实际选型还要核查订货规格、温度、焊盘与散热。[Vishay D/CRCW，文档 20008，第 2 页](https://www.vishay.com/docs/20008/dcrcw.pdf)

去耦应结合模块端已有电容、供电稳定性及布局选择。预留几只电容不等于供电签核，应测模块端最坏瞬态电压，并检查待机轨是否与所需唤醒模式匹配。

## 7. DP 显示连接单独处理

在采用 Intel Core 集成显示的常见桌面架构中，DP/DDI 发射通道来自 CPU 显示接口，不应把它们当作 PCH PCIe 信号去补线。还需处理 AUX、HPD、方向/角色、复用、必要的电气器件和显示固件配置。其他架构应根据实际显示源核查。[Intel Core 处理器 Datasheet 743844，§12.5.1，第 177 页](https://cdrdv2-public.intel.com/743844/743844-015.pdf)

只完成 PCIe/USB/电源边带不能宣称无线扩展坞显示已完成。DP 尚未实现时保留明确待办和未连接标记；MLDIR 等角色相关脚位按模块和显示方案确定，不能为消除悬空提示而随意接地。

## 8. Capture 原生坐标与全引脚验收

新增 OffPage、Global、Port 或库符号时，**实例 owner location 不等于电气热点**。应读取实际 Design Cache 中的 SymbolBBox、SymbolPinScalar/引脚局部坐标、镜像与旋转属性，并使用原生数据库 API 或一个已知接通实例校准对象类型对应的变换。

通用关系是 `目标 owner location = 目标世界热点 − 已校准的局部热点变换`。镜像轴不一定是局部原点；旋转电源符号也不应套用器件的经验公式。不同库版本的原点和热点可能不同，不要把一次测出的固定偏移当作所有符号的规则。

操作和验证顺序：

1. 冻结输入设计与库，并建立逐引脚的预期网络变更表，列明允许变化与必须保留的连接。
2. 用原生 Cache/API 和已连通模板证实热点、镜像、旋转及文字坐标含义，再批量放置；不得只看箭头尖端与线端是否视觉接近。
3. 图形预览按真实坐标绘制，不能把图元自动吸附到线端以掩盖空隙。文字与引脚、线、器件属性的避让应在连接正确之后独立复核。
4. 独立导入、保存、退出并重新打开实际 DSN，重新导出 XML 和原生 PCB Editor/PST 网表；脚本正常退出或导入器没有弹窗不构成成功证据。
5. 从 `pstxnet.dat` 建立全部物理 `refdes.pin → 网络分组`，并结合 `pstchip.dat`、`pstxprt.dat` 核对有效器件、脚号、封装和新器件定义。比较全工程全部引脚，不能只检查新增端口的网络名称。
6. 验证每条新网的完整成员，确认无孤立网名、错误跨接、漏地、错接相邻线、旧接口被占用或未授权变化；预期的串联电容、0R 分网必须单独列出。
7. 对原本等价的多网名/别名使用连接集合比较，同时保留名称变化报告；不得用忽略所有网络名的方法绕过漏接检查。
8. 最终分别保存电气验证、原生网表生成结果、可读性检查和剩余硬件/固件待确认项。PCB 导入、约束、实际布线与实测属于后续独立验收。

项目专用预览、审计结果、临时 XML、PST、DSN/BRD 和版本指标留在工程目录；学习库只保存本方法及可参数化复用的脚本。


## 原生连接命名空间与旋转符号的验证

电源Global与OffPage翻页符号即使显示同名，也可能不会形成同一原生网络。不要仅比较文字；必须在Capture实际导出的PST中检查供电源、受电器件等所有引脚是否属于同一完整连接分区。

旋转符号时，XML的PortInst局部热点不会随实例rotation自动改写。需要从同库、同姿态、已有真实接线的源实例校准坐标变换；再原生保存重开、重新导出网表并全引脚比较。电容串在水平差分通路时，可将两只电容水平放置、P/N上下靠近；去耦电容按电源和地的实际连接排布。

PCB网表同步先在冻结副本上用原网表做no-op控制，比较旧器件位置、角度、正反面、用户属性、缓存封装与STEP映射及物理铜形，再执行真实逻辑ECO。使用保留旧放置的选项也不能替代读回校验；新增器件应留为未放置，布线与制造签核另行进行。


## DP主链路、AUX和HPD的实际补接方法

先从保存的原生网表确认四个主链路Lane、AUX和HPD资源空闲，再核对原工程库球位。按平台显示端口映射表匹配HPD，不能用相似信号名字替代端口表。例如Intel600 PCH的端口C对应DDSP_HPD2，而不能直接按名称选DDSP_HPDC；同时确认VCCPGPPIR实际供电电压。

主链路和AUX各线的耦合与偏置须分别核查；100nF是通用DP资料中的常见选值，不能当作某模块完整指南已经核验。AUX源端100K偏置的方向为AUXN上拉、AUXP下拉，位置在源端耦合电容与连接器之间。DP++、eDP、重驱动器和内部模块可能有不同要求，按实际架构确认。保持Lane编号和P/N极性；固定无线显示发送应用中，M.2模块作为DP sink，MLDIR方向终接属于卡侧，主板不应无依据驱动。

画布上仅有本地Alias或带间隙的占位线不表示已跨页连接。加入耦合件时，电容两侧不能保留相同本地Alias，否则可能被网名短接。用实际OffPage构造跨页连接，原生保存重开后比较完整引脚分区。原理图接线完成还需要BIOS/VBT的DDI/HPD映射。

PCB导入日志零错误、旧器件位置相同、逻辑网表一致或旧引脚邻接保持，都不能代替铜线几何比较。如导入触发无关电源线段变化，保留失败证据，禁止把它当成通过板交付；先查清副作用后再发布。
