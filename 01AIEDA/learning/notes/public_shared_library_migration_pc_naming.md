# Cadence公共库迁移与同类别尺寸唯一_pc命名

适用范围：Capture／Allegro 17.2的既有工程迁移。先把本次工程、Capture公库、PSM、PAD、器件库及环境目录作为显式输入；本文不绑定某个工程的尺寸、引脚数、文件SHA或放宽规则。实际工程计划、XML、网表、板文件和验收放工程根；公共库的新增／修改及验证记录放学习库的 library_maintenance／日期_任务 目录。

## 先明确三种名字

- Capture原理图符号按功能、材料、极性和真实引脚schema共享。同一种电阻图形可同时用于多个PCB尺寸；不按位号或阻值复制符号。
- Capture实例的PCB Footprint必须与Allegro器件实际选用的封装名一致。这里统一为例如 c0402_pc、c0603_pc、c0805_pc、r0402_pc、r0603_pc、fb0603_pc。
- Value／User_Value、型号、采购字段及原AD追溯属性是另一类信息。改库来源和封装名时不顺带修改它们；空贴NC_及未知值占位同样保持。

若用户要求同类别、同尺寸只保留一种_pc，普通R/C不再添加wide、line、frame、版本号或旧数字后缀。先审查真实类别和尺寸，再显式选定一种标准定义。保险丝、特殊跳接／取样连接、阵列、极性电容等不能仅凭0402／0603字样归并。电解电容可按确认过的直径、脚距、极性schema命名。电感／磁珠也需按真实器件类别和必要的尺寸确定标准。

## 同尺寸统一需要区分两种操作

**只改身份名**：旧封装与标准定义的完整物理结构一致，保留脚号、焊盘、旋转／镜像、偏移、图形及全部属性。不能仅凭外框、文件名、引脚数量或包围框宣称一致。

**统一为一个标准定义**：同尺寸旧封装仍有不同焊盘位置、线条或其他结构时，选择一个标准会产生真实几何变化。把标准来源、每个受影响位号、旧／新定义和预期几何差异先冻结；随后核全部物理脚号、焊盘世界坐标、实际铜连接及受影响区域。源工程无后缀定义与本机同名公库也可能不同，二者都要实测；选哪一个由本次明确策略决定。重命名成功不能代替这些检查。

## 优先复用已有公库，缺少的才新增

1. 冻结最新设计、原始库和公库清单，记录绝对路径、大小及SHA。递归列出本机全部相关库，而不是只查几个常用文件；原生导出失败单列为失败，不能据此判断“库里没有”。
2. Capture对比完整有序Package，包括PhysicalPart映射、Normal／Convert视图、针脚位置／电气类型／可见性／共享与Global标记、图形、字体、默认属性及未知字段；库级DefaultValues另作完整比较。仅作明确的来源身份归一，包／Cell更名必须另有一一映射。内容相同但库级默认字体不同，不能直接宣称完整可替换。
3. 网络符号按Global、OffPage、Port各自类型核对。相似地符号或箭头不跨电气类型合并；来源迁移不改网络名、热点或文字。
4. PCB用实际原生PSM／DRA／PAD内容和引脚映射选库。公库同名但不同定义时，选明确的新名补入，不覆盖用户原有文件；编辑前检查硬链接身份，避免连带修改别名。
5. 只给已证明缺少的对象新增共享OLB。用源设计的真实默认字体／primitive设置构建新库，原生保存后换进程重开，再核完整库内容。字体克隆使用本机SDK返回的全部LOGFONT字段，不根据XML里较少的字段猜值。

## 以最小原生修改迁移Capture

先生成逐对象冻结清单：缓存对象的类型／名称／原来源／新来源，以及页面实例dbId、实际位号、原／新PCB Footprint。每个目标都要能精确定位；预检查全部通过后才修改。

只改来源时，优先使用已验证的原生ReplaceSourceLibName与库对象SetSourceLibName；只改封装字段时，修改现有实例的PCB Footprint属性。不要为迁移来源重新创建实例，也不通过全图XML重建去移动电气对象。原生保存后独立重开，全有序XML仅逆转计划中明确列出的字段及实际记录的最小保存元数据，要求还原源树。不得全局忽略dbId、坐标、Junction归属、属性次序或字体差异。

多单元器件应分别使用基本Reference与带单元字母的ReferenceDesignator，避免把PCH／CPU各单元误当不同物理位号。缺少的User_Value与显式空字符串不同；缺失状态和原生读取失败码保留，不能为方便校验写成空串。

DSN内部Design Cache、BRD内嵌symbol／padstack定义是设计保存的一部分。删除工程外置库副本不能删除这些必要内嵌内容。

## 已布线PCB的安全迁移顺序

netrev的Always（-y1）即使保留元件位置，也可能重建连通路径。旧板若存在跨网络线端或历史数据库附着，重建会产生新的分区拆分／合并；日志零错误、逻辑网表相同、线路与铜的几何并集相同，都不能证明实际连接未变。因此，不把Always作为已布线板批量换库的默认步骤。先保留源板的真实连接图，并用无封装变化的网表更新control区分原有问题与迁移引入的问题。

已有布线的封装统一，先按逐位号冻结映射调用经过本机验证的axlAltSymbolReplace，保留既有实际连接对象。逐批检查放置、姿态、全部pad及实际连接；在封装身份与目标定义就绪后，再用新PST的IfSame（-y2）同步逻辑Package。未先替换实际封装时直接IfSame，也可能把不匹配器件取消放置，因此每次仍核全部组件和物理pad，不能只读netrev退出码。

批量symbol／mask处理可用axlDBCloak的shape范围减少重复动态更新，配合分批检查点；这只是执行效率措施，不是连接或铜验收。对象修改后刷新父symbol及children再读回，避免使用旧dbId缓存。SKILL脚本使用UTF-8无BOM或纯ASCII；保存／恢复检查点都只作用于本次独占副本。

连接验收使用axlDBGetConnect读取的完整物理成员分区和实际邻接。每个物理pad保留稳定、带类型的身份、原／批准位置和重复出现序号；机械pad、重复脚号和无网络引脚不省略。nil与“net对象存在但name为空字符串”分别编码，空串也不能直接等同于电气NoConnect标记。若只以(ref,pin)作字典键，会静默覆盖重复编号或无编号pad。分区总数相同仍不够，成员集合、重复次数、逐pin网络与实际路径两端都须比较。

标准pad变大、覆盖旧线端，不表示数据库已把该pad附着到线端。若发现孤脚，先确认逻辑网络和真实邻接，再冻结局部修复。即使短线能完全放在pad铜内、铜并集没有变化，新增连接仍是明确的电气修改，需独立记录尺寸、层、网络和端点，并在保存／重开后重新核GetConnect、全体物理pin、铜及规则；不能凭目视接触关闭问题。
## 默认封装与未来放置

现有实例有显式PCB Footprint，不等于库模板默认封装已迁移。分别审计Package默认、Cell／视图默认和每个实例的显式覆盖。若只迁移现有工程，保持经过完整比较的模板默认不变，并在库说明写明新放置时要明确选择当前封装；不能让操作者误以为旧默认已自动更新。

若还要改变模板默认，单独冻结逐Package／Cell计划，同时更新共享库与对应Cache，再重新做完整默认属性、有效继承、PST及放置复用检查。R/C共享模板不按PCB尺寸拆符号时，可以保留空封装默认，让实例明确选择尺寸。

Tcl 原生对象必须按已验证的具体类型调用。页面迭代器返回通用 DboPartInst 时，先用 DboPartInstToDboPlacedInst 得到 placed 对象，再调用该对象的 GetPackage 取得实际缓存 DboPackage；不能因另一个脚本的变量也叫 inst 就认为 wrapper 相同。Package 的 GetPCBFootprint/SetPCBFootprint 与实例的显式 PCB Footprint setter 是两种作用范围。先绑定全体对象及原值再改，立即读回，并用独立重开完整 XML 门证明只改了冻结属性。失败的原生副本和日志保留，修正 wrapper 用新的脚本及输出目录，不把纯 Tcl 语法检查当作原生调用成功。

对默认封装更新，比较实际设计 Cache 与新共享库的全部命名对象及完整有序子树。只允许在核对来源身份后处理对象根的 sourceLibName 差别；图形、脚号、字体、其它默认属性和未知字段不省略。库级 DefaultValues 另做完整比较，并绑定原生完整 LOGFONT/默认设置的保存及重开读回。新库尚在 staging 时明确标记为候选，实际公共路径发布并重开后再写公共来源一致的最终结论。

## 独立导库验证与旧名称残留

File→Export→Libraries对应dlib。官方说明导出设计内全部库元素，批处理的-a也明确是全部Package符号；没有可据以保证“仅导出已放置器件”的筛选承诺。因此先在保存并独立重开的设计上枚举design的全部symdefs，记录name、type、instances数，再与实际导出比较；只统计placed symbol名称不够。

本机独立批处理入口是C:/Program0/Cadence/SPB172/tools/bin/dump_libraries.exe。先建立全新空输出目录，将受保护的冻结板副本放入其中，并以该目录为cwd执行：

    dump_libraries.exe -ac "<受保护板副本的绝对路径>"

-a导出全部Package的DRA，-c同时生成PSM；默认连PAD等依赖一起导出，-x才禁止依赖。完整层叠PAD内容另按适用的-e选项和原生PAD XML验证，不能用Package名字相同代替定义／层叠一致。独立dump_libraries帮助未列-nographic参数，不向该exe拼接未文档化开关。

也可在独立Allegro会话对精确列出的symdef调用axlWritePackageFile(symdefDbid outputDirectory)，导出单定义及依赖。输出文件根名是定义名的小写；比较时按大小写不敏感的stem做完整名称集合、重复次数和缺失／新增检查。导出退出码、dump_libraries.log及全部产物SHA与同一冻结板SHA绑定，源板／副本前后SHA仍需核对。

官方说明未使用symdef会在保存／刷新等过程中被清除；确有旧unused定义时，只对冻结旧名、类型为symdef且instances为空的对象考虑axlDeleteObject，并保存重开复验全部定义和设计不变量。不能把component或net传入此清理，也不采用ripup。已有实例的标准定义不得删。

每次验证和用户正式导库都选择全新空目录。导出会覆盖同名文件，不会替你删除上次导出、这次不再生成的旧文件。旧目录里的C0402_3_1或R0402_PP可能只是历史残留，不能据此判断当前板仍在使用，也不能据一次新导出宣称旧文件已自动清理。

## 验证顺序与发布

- 原生保存、独立重开，核完整XML、实际引脚热点、显示和网格；仅改身份／封装属性时也要证明所有电气点未动。
- 重新导出实际255字符PST，逐位号比较完整器件body、脚号、逐脚网名、分区及装配成员。预先预测库来源导致的实例路径／primitive身份变化，精确解释；不要按失败差异反向扩大白名单。
- 导入PCB后，按明确封装替换计划核每个pin、实际焊盘／via、铜、规则和源／新板差异。保留原始严格失败报告，另写有依据的有界比较，不能把原FAIL改成PASS。
- 从最终公库实际路径做不保存试放，至少覆盖R、C和一个多单元符号。核实际来源身份、Package／全Cache数量不增加、真实针脚及世界热点。只在任务独占会话试放，结束时丢弃设计；保护输入SHA，不操作用户正在编辑的窗口。
- 最后重绑OPJ、环境、导网表和打开工程入口，使用公库绝对路径或经过同机验证的路径规则。移除新版本中确已无引用的外置库副本前，扫描所有入口并做公库环境独立打开检查。既有历史版本和用户明确保留的原件／压缩包不随本次清理删除。

公共库比较工具：[compare_shared_public_library.py](../scripts/capture_xml_tools/compare_shared_public_library.py)接受显式expected／actual XML及全新输出目录，比较完整命名对象集合及有序对象子树、库级全部默认内容；仅归一库根的输入文件路径。当前反测要求输入包含标量pin、Line和DefaultFont，不满足时停止，不能跳过反测后声称通过。命令格式：

    python compare_shared_public_library.py --expected <已审查的候选OLB_XML> --actual <新进程重开OLB_XML> --out <全新报告目录>

接口和边界参见[来源重绑与缓存复用](capture_cache_reuse_and_origin_rebase_xml.md)、[自己的库优先](capture_user_library_first_templates.md)、[Value显示约定](rc_value_display_conventions.md)及[NI／NC_装配状态](population_nc_prefix_workflow.md)。这些方法不改变既有课程状态，也不表示工程的全板DRC、SI／PI或制造已完成。

验证 Allegro 包是否真正从公库重新加载时，可以把已保护 SHA 的编译 PSM 独立复制为本次临时唯一名字，在独占的原板副本中试放，以保留相同单位、实际叠层和完整字体参数上下文。必须从 `axlDBCreateSymbol` 返回的 symbol 直接取 definition，要求新 DBID 不等于原缓存且别名身份精确符合计划。创建后立即重读父对象的 symdefs 集合可能得到尚未刷新的缓存，不能据此判定复用或未加载；也不能仅依据临时文件名字断言已经绕开缓存。前后完整字体表应一致，试放过程不保存设计，公共 PSM 原件及全部依赖逐 SHA 保护。

包缓存未复用并不证明焊盘未复用。同一板中的同名 PAD 可能仍使用板内缓存，必须另做完整制造字段核验：用官方 `dump_libraries -ac` 导出真实板内 package 及依赖，再把关注的 cached PAD 与当前公库 PAD 分别复制到独立新目录，用 `padstack_editor -xo` 导出完整 XML。保留钻孔、镀铜、全部层、regular／thermal／anti、阻焊、钢网、选项、未知字段和内部顺序；只有已经明确列明的单位换算可使用精确系数，不得以几何容差隐藏差异。若源存储单位与板单位不同，格式单位／精度应列入单独台账，制造尺寸要求精确物理数值相同，不能按显示舍入后判等。

一个历史模块可能同时包含本次改成公库标准的少数 package、与原公库长期不同的既有通用 package，以及只存在于模块内部的专用连接器／图框缓存。应分别证明新标准包的完整公库图形与制造字段，以及未更改缓存相对源板的完整图形、字体、STEP 和未知属性守恒。没有外部 PSM 的内部缓存不能记录成“已外置”；它们也不能因为名字不在公库中就当作垃圾删除。

网表、pad 网名和原生连通分区均正确，也不能代替制造铜审计。标准化 land pattern 后，旧 thermal 路径可能失去一部分铜；要从原板原生对象证明其 kind、owner、层、网络和实际完整 stroke，区分源路径与原 pad 铜。若需恢复，只采用冻结的真实源路径，并以原生多边形等式证明“修改后铜 = 修改前铜 ∪ 获准源路径铜”，同时证明没有源外铜、原铜损失或新增异网重叠。路径对象因原生合并／拆分而变多或变少时，分别记录对象数和实际铜，不以实体数量代替材料等式。保存并独立重开后仍核全部实际 pin、via、完整连接分区成员、文本／属性、逻辑反馈和约束。

完整设计 symdefs 应按 type 清点。PACKAGE／MECHANICAL／FORMAT 的选定包快照与全部 SHAPE 缓存不是同一个计数；SHAPE 的 instances 为 nil 仍可能由 PAD 引用，不能因此删除。跨进程比对原生图时，运行期 DBID 会变化，必须记录明确、一一且可逆的有类型 ID 对应：图内对象拥有完整原生 payload；图外实例由独立的全实例姿态／引脚／属性台账证明语义，唯一 design parent 由完整约束／设计属性门证明语义。除这些明确身份指针外，所有图形、字体、属性、未知字段和内部顺序仍精确比较；不要删除所有 DBID 字段或使用数值容差来消除差异。
