# 按原厂资料确定接口等长与时延预算

本方法用于把已迁移的接口分组变成有依据的时序约束。实际器件型号、原厂文件、表格、网络成员、计算结果和板文件放在对应工程根；学习库只保留方法。参见[规则迁移与验收](ad_to_allegro_constraint_migration.md)。

## 先确认适用范围

从原理图器件属性、真实引脚、BOM 和实际采购型号交叉核对控制器、芯片组、端点、内存模组、目标速率及拓扑。符号库名称、页面标题或连接器标称能力不能单独证明实际芯片型号与工作代际；相互矛盾时保留原始记录并列为待定。

查适用于该平台和修订的原厂布线指南、设计指南及封装补偿资料。公开数据手册的引脚定义、最高速率和接收器电气规范，不一定包含可直接填写的 PCB 长度容差。其他处理器、FPGA 或参考板的数值只能用于理解方法，不能移作当前平台要求。

每个候选数值至少登记：原厂网址、文档号/修订/日期、物理页及书页、表格或条目、适用型号/速率/拓扑、路径端点、单位、上下限或偏差定义、封装与连接器是否计入。没有找到适用数字时记录“尚未取得”，不要据此宣称所有原厂资料都没有。

正文提到针图、封装延时表或计算工作簿时，核对实际下载版本的附件清单和链接内容。文中引用过某个附件，不等于当前 PDF 已包含它；缺失时记录修订、来源和读取结果，不生成替代数据冒充原附件。

## 按原厂度量重新检查分组

| 接口内容 | 必须分别确认的要求 |
| --- | --- |
| DDR 数据 byte | DQ 相对所属 DQS 的路径预算；单独 DQ 组内最大最小差不能代替它 |
| DDR 地址、命令及控制 | 相对接收端 CK 的要求、信号类别、rank 与模组拓扑，不能默认全部同一偏移 |
| 差分时钟、DQS、高速串行对 | 正负两条完整路径之间的内部偏斜；静态全长与沿途动态相位分开 |
| 多 lane 链路 | 对内偏斜、跨 lane 偏斜、发送/接收方向及独立端口分开；先查是否确有跨 lane 限制 |
| 串联电阻或 AC 电容 | 列出两侧 net、器件引脚及真正的起终点，核实 XNet/明确 PinPair 和器件模型 |

单条正腿、差分两腿平均、总铜长和特定引脚路径是不同指标。规则中使用的指标必须与原厂表格相同。内部有交换关系时，先证明真实 DQ/DQS 与物理脚映射，并核对是否需要 BIOS 配置。

## 不用未确认的层叠换算 ps 与 mil

读取源设计和目标板的实际层叠，逐项比较成品厚度、铜厚、材料、频率相关 Dk 和参考平面。旧兼容字段、另存字段及导入后的默认值可能互相矛盾；介质常数为零也不能作为传播模型。优先取得板厂确认的成品层叠，不为得到一个数字而自动选择其中一套。

原厂预算若包含封装、主板、插槽或模组，先确定补偿边界。不能把整个通道预算全分给 PCB，也不能重复扣除已经包含的封装项。不同层传播速度、过孔和路径端点尚未核实时，不把时间限值按一个全板固定系数转换成长度。

## 标准档与超频目标分开管理

用户提出超频目标时，分别记录可回退的基础档和希望验证的目标档，包含数据率（MT/s）、具体模组、Rank／RawCard、Gear、时序、电压及 BIOS 训练条件。后续明确的用户选择覆盖此前目标，旧记录保留为历史，当前配置文件应指向最新选择。

处理器和芯片组支持内存超频，并不等于当前板已达到任意超频数据率。XMP／手动超频依赖模组 SPD、处理器、板型 BIOS 与训练；Allegro 的电气约束用于检查板上路径。原厂 XMP 认证和主板 QVL 也要核对完整模组、CPU、板版本和 BIOS 组合。

两档分别建立原厂预算和验证状态。DDR 的外部 CK 频率为数据率的一半，UI 为数据位周期；这些是计算基准，不能当作允许的布线偏斜。不要把基础档容差按频率比例缩放，也不要任取 UI 的某个百分比作为原厂预算。目标频率明确而封装、模块或原厂窗口未确定时，保持预算空值，不自动填写 Gear、电压、CL 或调宽容差。

目标配置、待填审核表、原生已应用规则、BIOS 已选档位和硬件实测通过分别记录。仅生成两个 JSON／CSV 计划，不能称为已在 Cadence 中建立两个生效配置。

## 在 Allegro 中落实与验收

1. 固定已有板、配置和 SHA，在独立副本操作。逐组登记旧值、原厂候选值、适用性、采用指标与待定项。
2. 差分内部偏斜核对 Electrical 的 Phase Tolerance；普通相对路径核对 Relative Propagation Delay 的参考路径及必要时的 PinPair、Delta、Tolerance 和路径类型。Net／XNet／PinPair 的选择跟随原厂度量，不要用跨 lane 代表组替代差分内部检查。
3. 原厂要求计入封装时，核对真实 `PIN_DELAY` 数据、单位及传播速度因子，并确认 `PIN_DELAY_ENABLED` 和对应分析选项生效。仅有一个延时表或一个开关均不够。
4. 保存后独立重开，逐个读回端点、成员、继承、单位、参考路径及模式；用明确路径的小副本验证检查实际报告所期望的偏差。
5. 比较原板几何和逐脚物理铜连通。时序约束保存成功、原厂预算已确认、现有布线已满足预算、完整 SI/DRC 通过分别记录。

本机 Cadence 17.2 官方帮助依据：`doc/propref/properties.html` 的 `RELATIVE_PROPAGATION_DELAY`、`DIFFP_PHASE_TOL`、`DIFFP_PHASE_TOL_DYNAMIC`、`PIN_DELAY` 与 `PIN_DELAY_ENABLED`；`doc/cmug/02objects.html` 的 Differential Pairs。此处为方法依据，未声称已在具体工程完成 GUI 或时序验证。

数字尚未有适用原厂依据时，预算字段保留空值并阻止自动批量写入；已有迁移值继续明确标注临时。待补齐资料再生成新配置，不能把“审核清单已完成”写成“原厂规则已设置”。
