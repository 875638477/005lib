# 空贴器件的 NC_ 前缀与独立验收

本文记录将已确认的 `NI`／DNP 装配信息恢复成明确显示前缀的方法。`NC_` 在此是用户约定的空贴标识。它不表示引脚 No Connect，也不改变网络、封装、BOM 或 PCB 转换资格。配合 [R/C Value 格式与工具](rc_value_display_conventions.md)使用；通用 formatter 只处理明确输入，不扫描工程替用户判断装配状态。

## 先固定当前状态与证据

以当前正式、已保存的 DSN 为基线，记录其 SHA、配套 OLB、当前 PST 和 PCB；原生只读导出当前 XML／有效属性。若输入已改变，重新读取，不把早期全工程 Value 表覆盖到新版本。原始来源用于证明空贴含义，写入的 before 值必须来自当前状态。

逐器件保存源字段、原文、文档位置和判定依据。独立末尾 `/NI`、明确装配字段可作为证据；Description 内的标记应先核实其装配含义。型号、封装、位号或任意历史串包含字母 `NI`，不能自动判为空贴。遇到“已装”和“空贴”证据冲突时停止生成该项。

空贴状态、BOM 排除、PCB 排除是独立维度。分别记录现有 `BOM_IGNORE`、`PSpiceOnly`、`ConvertToPCB` 及其实际命名变体；不根据显示前缀切换它们。空贴器件仍可能作为物理成员存在于网表中，原来排除的器件也应保持原有资格。不要设置电气引脚 NC 或删除网络。

## 冻结最小文字计划

逐实例用页名、对象身份、位号和单元定位，分别列出 `PartValue` 与实际画布 `User_Value` 的精确 before／after。一个物理位号可有多个原理图单元，必须枚举，不能假定 ref 唯一。

- 对已统一格式的 R/C，按明确策略在当前完整串前加一次 `NC_`，保留阻容值、实际封装、电压和精度。
- 对非 R/C，`PartValue` 可能是模型名称，`User_Value` 可能是较长描述。分别处理各自原串，不能用描述串覆盖模型／网表 Value。只有经授权的独立末尾空贴标记可移除；不能替换封装内部的同名字母。
- 只有空贴标记而没有可核实的实值时，不编成 `0R`。通用 formatter 保持 `REVIEW_NEEDED`。若用户允许工程专属 `NC_TBD/...` 或其他占位显示，单独记录依据和待定性质；不能把占位当作已核实物料参数。
- 已有前缀保持幂等，不生成 `NC_NC_`。对非目标器件、全部既有属性、装配标志和源用户库保持严格保护。已有有效装配注释足够时，不为统一显示批量新增可能进入 PST 的属性。

计划仅授权列出的 Value 字段及必要的显示位移。延长文字后重新检查 Ref／Value 与本体、针文字、网络和导线的关系；不能以减少碰撞为由让值远离器件。见 [文字几何与可读性](capture_text_geometry_and_readability.md)。

## 保存重开后逐域验收

在隔离副本中执行精确 setter，保存并独立重开。对所有目标核对实际 Value、User_Value、DP 显示串和有效属性；完整 XML 逆变换仅恢复已批准字段，其余有序图形、引脚、网络、属性和对象引用严格相同。运行时 ID 只能在证明对象双射后处理，不能整体忽略。

导出 PST 后区分 placed 实例与物理器件。逐物理位号只还原预先计划的 `VALUE`，完整比较针号、针名、类型、脚序、封装和其余器件定义；原来排除的实例逐项保留来源证据。非 R/C 的 PCB Value 以实际 PST `VALUE`／计划 `after_value` 为准，不用画布 `after_user_value` 代替。至少用一个两者不同的虚构对象做负控制，确认误用显示串会失败。逐脚网络名及连接分区另外比较。

PCB 只在最新板副本导入。若器件 Value 文本与包围框更新而严格字节检查失败，保留原 FAIL，不笼统忽略 text／bBox。使用 [原生文本 owner 审计](rc_value_display_conventions.md#pcb-value-text-owner-audit)将每条变化绑定真实 symbol/ref 和预计划 PST Value，逐项锁定字体块、层、坐标、姿态、镜像、对齐、重复次数及其余字段。

包围框计算要按本轮实际 cohort 的 TextBlock 和字符范围重新验证。只有实测支持的单行 ASCII、字宽与字距、对齐和旋转／镜像组合，才可用精确十进制计算逐个预测四个边界值，并与原生 `axlDBGetExtents` 对照。不能沿用另一次工程的对象数量、旧板 SHA 或“相似字体”结论。其余完整几何多重集、铜连接分区、引脚、放置和规则仍需严格比较。

CFX 中因新 Value 引起的生成名称或定义合并，应按实际 source／candidate PST 的每个位号展开完整定义再比较；不能整体忽略 PartDefn／Gate。原始严格失败、独立有界证明和新输出板身份分别保存。此流程不代表 GUI 全页像素、DRC 或制造验收完成。

## 文字边框与原生字体参数

前缀中的下划线可能增加字形下沿；完整字符串的矩形边框会压到导线，即使导线恰好穿过字间空隙、实际字形相交面积为零。对 source/candidate 分别核整段文字边框与导线、引脚、本体及相邻文字边框的新增和增长相交；保留原有问题台账。局部预览必须同时包含所属器件与新文字，不能只裁文字后据“无碰撞”允许远移。必要时以预先冻结的单个实例字体宽度等显示字段解决，并精确保留其他字号、字体、旋转、对齐和电气坐标。

Capture Tcl 的 `DboTclHelper_sMakeLOGFONT` 构造器第一个参数使用字体名的 Tcl 字面字符串，如 `Arial`，不能传 `sMakeCString` 返回的指针句柄。否则可能把句柄文本当成字体名。该用法可从本机官方 `tools/capture/tclscripts/capPSpiceModelApp/PWL/Digital/Gates/OR/tcl/PwlORSymbolCreate.tcl` 的 `writeSymDisplayProp` 核对。保存前逐字段读回完整 LOGFONT、实际显示串与位置；任一字段不符就中止副本保存，再独立重开核 XML。接口失败不能通过放宽字体名称检查来绕过。
