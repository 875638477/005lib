# AD 转 OrCAD／Allegro：可复用操作方法

整理日期：2026-10-23。本文保存转换方法、接口注意事项与验收标准。每次实际转换的输入、脚本配置、日志、修复清单和工程结果归该工程目录；本文不作为某个工程已验收的证明。

以下方法来自 Altium Designer 18 与 Cadence 17.2 的实际操作。其他版本先核对安装目录、帮助、菜单和最小测试结果，不批量重放历史修复脚本。

按界面操作的步骤见[人工操作教程](ad_to_cadence_gui_workflow.md)。该教程不含代码；本文补充缓存、原生审计与验收原理，两者都不保存具体工程副本或结果。

专题方法：[Port／Alias网络文字排版](capture_netlabel_layout_rules.md)、[Capture到Allegro网表排错](capture_allegro_netlist_troubleshooting.md)。前者区分显示修正与连接，后者区分名称截断、旧网表、库路径和真实封装问题。

[AD规则迁移到Allegro](ad_to_allegro_constraint_migration.md)进一步说明规则作用域与优先级、真实差分／匹配组、路径类型、差分间距下限、DCFX／TCFX完整回载和独立验收；不以网表转换成功推断规则已迁移。

## 1. 目录与参数约定

开始前明确三个根目录：`<学习根>`、`<工程根>`、`<Cadence根>`。不要从旧笔记推断盘符、用户名或版本。

| 保存内容 | 位置与规则 |
| --- | --- |
| 通用步骤、方法、接口陷阱、验收模板 | `<学习根>/learning/notes/` |
| 完全参数化且无工程默认值的通用工具 | `<学习根>/learning/scripts/`；不在这里输出项目结果 |
| 原始 AD／Cadence 工程与交付包 | `<工程根>`；原件保留，只修改工作副本 |
| 本次专用脚本、配置、日志、报告、截图和备份 | `<工程根>/conversion_work/` 或用户指定的工程子目录 |
| 项目转换记录、差异与开放问题 | `<工程根>/转换记录.md`，详细证据放工程内并用相对链接引用 |
| 历史失败试验 | 工程自己的归档目录，保留来源与状态，避免与当前交付混放 |

本规范区分通用学习内容与实际工程。不得把新工程的 DSN、BRD、库副本、PST、XML、大型运行结果或临时产物写到学习库的 `staging`、`examples`、`logs`。脚本名称通用不代表内容通用：包含固定工程路径、位号、页数、哈希或器件映射表的脚本仍属于该项目。

可复用工具至少显式接受：输入路径、输出目录、软件安装根以及需要的配置文件。拒绝覆盖原件和已有输出；校验最终绝对路径，复制后核对 SHA256。参数表、位号映射和本机路径保存到工程内，不固化进通用工具。

## 2. 固定输入身份与转换目标

1. 清点 `PrjPCB`、全部 `SchDoc`、`PrjPCBStructure`、`PcbDoc` 和现有 Cadence 文件，记录格式、大小和 SHA256。校验工程引用的文档确实存在。
2. 复制到工程内的独立工作目录，逐项比较哈希。后续编译和转换使用副本。
3. 确认目标是可编辑 Capture 原理图，还是只导出 PCB 网表。AD 的 `OrCad/PCB2` 网表输出不能替代可编辑 DSN 转换。
4. 在 AD 工作副本编译项目，保存消息和网络作用域配置。结构文件较短不能单独证明缺页；由源软件重新生成并核对，不猜写结构。
5. 保存源原生编译结果中的物理引脚和网络归属，作为电气对照基准；另保存 PCB 原生 pad、器件和网络基准。

原理图和 PCB 可能原本不同步。先分别证明“目标原理图忠于源原理图”和“目标 PCB 忠于源 PCB”，再处理两者对接差异。差异必须列明源证据及最终取舍。

## 3. 转换与工程建立

1. 检查目标版本提供的 `File > Import > Altium Schematic Translator`。转换器要求的 ASCII 输入格式及项目结构以本机帮助为准。
2. 选择 AD 工作副本项目和工程内全新输出目录。保存完整转换日志、异常文字和未支持对象清单。
3. 转换结束后确认实际 DSN 路径、大小和新鲜时间，再原生打开读取。没有弹窗、脚本退出或目录出现文件均不能单独证明转换完成。
4. 若未生成 OPJ，新建 PCB／Schematic 类型项目，加入本次 DSN，核对工程实际引用；不要把向导生成的空白 DSN 当作结果。
5. 从最终 DSN 的 Design Cache 导出配套 OLB，并把它加入工程。通用旧库不能改名冒充本次缓存库。
6. 逐页清点实例、唯一位号、多单元关系、引脚和对象类型。数量相同只证明覆盖，电气等价另验。

环境异常先查本机安装与进程环境。例如转换器查不到基础库时核对 `CDSROOT` 及其实际库目录；只为本次进程设置，完成后恢复。命令窗中的提示文字可能被解释为 Tcl 命令，须保存真正的错误堆栈与转换日志，不能只根据一行提示下结论。

## 4. 元件值、字符与属性

- AD ASCII 解析要识别 `%UTF8%TEXT` 等 UTF-8 字段，与 `OWNERINDEX`、源记录和位号建立对应关系。只读普通 `TEXT` 会静默漏掉元件值中的特殊字符。
- 分别核对 Comment、Value 参数、Capture Part Value 和用户显示属性。避免以统一的 `NA` 掩盖字段解码失败。
- 目标流程需要 ASCII 时，仅对约定的元件显示／导出值转换，例如 `Ω → R`、`µ/μ → u`、`± → +/-`、`° → deg`。保存原始字段和转换原因，转换表受控，遇到未覆盖字符停止并报告。
- 网络名、脚名、脚号和器件型号不能套用元件值替换规则；它们关系到连接身份，需单独评估。
- 同时检查实例、缓存 package 默认值和缓存 part 用户覆盖。只改实例可能被库更新覆盖，或导出 OLB 后重新带入旧值。
- 若 `Device` 等自定义属性与原生封装流程冲突，先把原文保存到明确的追溯属性，再清理冲突层次；之后比较全部物理引脚分区和其他属性。

## 5. 按物理引脚比较电气连接

稳定键使用完整物理位号与脚号；多单元后缀不得误当成不同物理器件。源、目标分别建立“网络 → 物理引脚集合”。比较分区关系，而非仅比较网名或网数：

1. 所有预期物理引脚存在且唯一，列出缺失、新增和重复。
2. 每个源网络的引脚集合在目标中完全保持；列出拆网和误并网。
3. 保留单引脚网络和 NC 身份，避免把所有未连接点合成一个虚假网络。
4. 局部同名标签、跨页 Port、Power 的作用域以源项目编译结果为准。同名并不必然同网。
5. 自动网名可以变化，但物理引脚集合不能无依据变化。受控名称限定须保存源名与原因。

重点核查 Port 和电源的真实 hotspot。Port 的接点可能位于图形原点或另一端；不能只用外观左上角。修正电源热点还要检查相连导线是否拉伸、交叉或新增连接。源零长度导线在目标中可能不形成有效网；使用合法短段前须查周围几何，并由原生网表确认结果。

坐标转换明确单位、原点、Y 轴翻转和半数舍入；负坐标须与实际原生接口一致。每项修复限定页、对象和来源，不能全局按名称猜接法。

## 6. 原理图与 PCB 的物理映射

先生成逐位号、逐脚差异表，区分缺库、名称别名、源逻辑脚／焊盘差异、机械 pin 和实际漏转换。

- 符号脚多于焊盘时，先查 AD PCB 与原厂封装资料。厂家明确缺脚的器件不能为了导入通过而补出不存在的焊盘。
- 同网的冗余逻辑脚与重复物理焊盘需要明确映射。只有源证据证明同网且目标机制合适时，才采用共享脚、短接声明或受控物理导出投影。
- Capture 17.2 实测的 `SetIsShared`、`PACK_SHORT` 等会影响活动引脚和 PST。先在小副本验证全部边界，再用于工程；缓存脚数、实例活动脚数与 PST 物理脚数可以不同，必须逐项解释。
- 源工程明确不入 PCB／BOM 的器件保持在原理图中，按目标版本实测的排除属性导出。本机 17.2 中 `PSpiceOnly=TRUE` 与 `PSPICE_ONLY` 行为不同；BOM 排除另核 `BOM_IGNORE`。不要仅依赖属性看起来正确。
- 映射后的对照基准由源物理网络和已批准映射生成，保存每个被折叠、排除、新增或重编号脚的依据。不得手改 PST 作为最终修复。

Allegro 的 component pin 枚举可能不含所有 symbol pin。机械脚和未关联逻辑器件的已有焊盘应从全部 symbol 检查，不能见数量较少就新增 pad。

## 7. 整套原理图显示检查

显示验收和电气验收分别记录，覆盖全部页面，不只修截图区域。

| 项目 | 检查方法 |
| --- | --- |
| 网络文字方向 | 按源每个标签的实际方向和位置比对，不能把所有标签按父线方向统一旋转 |
| 标签遗漏 | 按页、原文、坐标及对象类型逐处匹配；目标总数较多仍可能漏标，因为分支会产生重复对象 |
| 同一导线的多个名称 | 分别核对可见文字和实际网络分区，避免补显示时误并网 |
| 长网名、短引线、遮挡 | 核对完整字串、字号、间距、朝向和器件边界；在 Capture 界面逐页查看，必要时移动文字或调整局部布局 |
| 实心本体遮住脚名 | 将不需要的填充改为轮廓；可用同坐标四条 Line 替代矩形，保持引脚、定位和外形边界 |
| Port／Power 显示 | 比较名称显隐、方向、位置和真实接点；连接存在不代表文字完整 |

未渲染的离线数据库可能返回零值或未更新的文字 bbox，不能据此证明没有重叠。字宽估算大于单段导线只提示需要查看，不能直接判定文本截断，也不能盲目延长导线而造成新连接。没有 GUI／打印预览证据时，明确保留视觉验收待办。

## 8. Capture 保存、XML 与缓存库

原生 SDK 批处理先检查 `DboState` 和 NULL，按对象类型正确转换，再读取有效属性。对象能枚举不代表保存后包装完整。

若数据库保存异常需要官方 XML 往返：

1. 使用本机官方 `XMATIC_DSN2XML` 导出工作副本与 schema，保存日志。
2. 只修改明确的 XML 字段并生成逐项差异表，保留其他图形、属性和电气坐标。
3. 使用 `XMATIC_XML2DSN` 导入全新文件；是否保留内部 ID 按故障和本机接口验证决定。
4. 若共享／忽略引脚改变了活动脚，核查旧 occurrence 是否仍引用已忽略位置，不盲删其他 occurrence。
5. 关闭、独立重开，比较对象、几何、元件值、映射及原生 PST；内部 dbId 重新生成不能当电气身份变化，也不能用它掩盖真实差异。

从最终 DSN 导出 OLB 后，逐 package／part／pin 比较属性、物理脚映射、共享标志及可见性。`CopyPackageAll` 在本机操作中曾改变新增共享脚的脚号可见标志，应读回并修复后再保存、关闭和独立重开核对。

## 9. 私有库与网表导入

PSMPATH、PADPATH、DEVPATH 放项目自己的环境配置，读取确认实际命中路径。避免通过修改公用库或机器全局环境掩盖工程缺依赖。路径包含空格时按实际软件语法引用，不能把 JSON 转义当作 shell 引用。

生成并保留三份原生网表：`pstchip.dat`、`pstxprt.dat`、`pstxnet.dat`。读取完整日志与返回码，并检查全部页和多单元包装结果。本机原生导出工具 `pstswp` 会更新 DSN 包装元数据；最终交付路径再导出后，重新记录实际 DSN 哈希与读回结果。

严格导入 Allegro 的独立副本，保存完整 `netrev` 日志和 ECO。先解决库、名称、器件和脚号问题，不以自动拆线或忽略固定对象开关换取通过。退出码为零仍需核对日志与最终板的 package、symbol、脚号和网络。

命令模板中的输入、输出、软件路径、版本选项均由工程配置提供；运行前检查本机帮助。最终验证实际交付目录与私有环境，不能只测中转路径。

## 10. 重复封装去重与方向归一

0402、0603 等名称或后缀只能用来筛选候选。比较实际定义后再决定是否合并：

1. 展开焊盘全部层的形状、尺寸、偏移、局部角度、钻孔与槽孔及属性。包含铜、阻焊、锡膏与机械信息。
2. 比较所有本体图元、丝印、装配边界和固定极性／脚号文字。位号、数值等实例注记单独保存。
3. 对允许的旋转求等价变换，保留 pin 1／pin 2 对应；不把镜像与旋转混为一项。非对称槽孔和非正交焊盘保守处理。
4. 相同尺寸外观但脚距、铜形、掩膜、丝印或机械外形不同的定义保留。按结果选稳定的 canonical 名称，保存旧名、等价组和补偿角。
5. 使用原生替换机制更新工作副本，不删除重放器件。若局部定义旋转归一，同步补偿实例角度，保证绝对焊盘和引脚网络不变。
6. 替换后恢复全部实例文字元数据；所谓“保留文本”选项可能仍重排角度、位置或遗漏特殊层注记，必须逐条比较。
7. 同步 Capture 实例、缓存默认值和 part 用户覆盖，重新导出配套 OLB／PST，严格 ECO 后再检查主 package 与 symbol 是否一致。
8. 独立重开验证使用及缓存定义数、全部 pad 世界坐标、层参数、实际网络、显式走线／边界与物理铜连接。仅定义数减少不能证明合并完成。

原生图形可能以反向线段／弧或重组 path 表达同一几何。只对明确证明等价的表示差异归一；实际端点、线宽、弧向、层和多重集覆盖都要核对。容差只用于有依据的派生缓存字段，不能推广到真实铜或焊盘。

## 11. 保存重开、交付与剩余问题

按以下证据分层记录结论：

| 验证层次 | 通过应具备的证据 |
| --- | --- |
| 来源未改 | 原件操作前后 SHA256 清单 |
| 原理图覆盖 | 逐页、实例、多单元和引脚身份清单 |
| 电气等价 | 原生源编译与最终 PST 的完整物理引脚分区比较 |
| 物理映射 | 逐脚映射及例外证据、最终板网络读回 |
| 图形／库保存 | 官方保存后独立重开，属性／几何／OLB 比较 |
| 显示可读 | 全页 Capture／打印预览检查，问题处理记录 |
| PCB 导入 | 实际交付路径与私有库环境严格导入的完整日志 |
| 布线与 DRC | 当前板的新鲜未连接报告、物理铜核对和完成的整板 DRC |

存量 DRC marker 数、局部 DRC 或未完成的日志都不等于整板通过。逻辑网分区一致不代表铜已连通；导入成功也不代表布线或生产验收完成。断电／中断后的零字节、截断或含 NUL 尾部日志需重新执行受影响检查。

交付目录至少包含 OPJ／DSN、配套 OLB、需要的 BRD／DRA／PSM／PAD／device、项目私有环境、当前 PST、启动说明、转换记录、差异／开放项和最终哈希。压缩包解压到新目录后检查工程与依赖引用，区分“同机重定位通过”与“另一台电脑验证”。失败试验独立归档，启动入口只指向当前版本。

通用学习笔记只回写本次新增的方法与避坑；具体位号、数量、哈希、故障截图、详细运行证据和项目专用修复脚本继续保存在对应工程，避免下一次转换误用旧项目参数。
