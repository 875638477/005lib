# PADS 原理图迁移到 Cadence 修复流程
源文件: AP-MT7621+MT7612E+MT7602E.DSN (PADS 导入，改名为 08UsbIPMT_V1_00_00.DSN)
## 问题说明
PADS 导入的 DSN 文件有两类 OrCAD 不兼容问题:
1. Pin Number 为空 (ORCAP-36022) - R/C/L/Header 等被动元件
2. Pin Name 重复 (ORCAP-36041) - MT7621/MT7612E/MT7602E 等 IC
## 修复步骤
### 第一步: 备份
复制一份 DSN 文件作为备份，防止修改出错
### 第二步: 运行诊断脚本 (只读，不修改任何内容)
打开 Tcl 命令窗口: View → Command Window
```
source {D:\001DIY\023USB\08UsbIPMT\01sch\diagnose_pins.tcl}
```
输出所有有问题的元件清单，确认问题范围
### 第三步: 运行修复脚本
```
source {D:\001DIY\023USB\08UsbIPMT\01sch\fix_pads_pins.tcl}
调试用的
source {D:\001DIY\023USB\08UsbIPMT\01sch\debug_api.tcl}
```
脚本自动修复:
- Phase 1: 扫描找出哪些 Part 有空 Pin Number
- Phase 2: 通过 Package/Device API 修复有正常 Package 结构的 Part 的 Pin Number
- Phase 3: 修复所有重复 Pin Name (加后缀 _2, _3...)
### 第四步: 手动修复剩余 9 个 Part 的 Pin Number
这些 Part 是 PADS 导入的扁平结构，没有 Package/Device 层级，Tcl API 无法设置 Pin Number。
需要在 Design Cache 中手动编辑:
1. 在项目树展开 Design Cache
2. 双击以下每个 Part 打开 Part Editor
3. 双击引脚 → Pin Properties → 填入 Pin Number (和 Pin Name 相同)
4. Ctrl+S 保存 → 关闭 Part Editor → 弹出 "Update Current?" 选 Yes
| Part 名 | Pin1 Number | Pin2 Number |
|---------|-------------|-------------|
| R | 1 | 2 |
| R0_5%_S0805_0 | 1 | 2 |
| 0.1UF/25V_+80%-20%_CC_S0603 | 1 | 2 |
| CAPACITOR NON-POL | 1 | 2 |
| CAP NP | 1 | 2 |
| INDUCTOR | 1 | 2 |
| CAPACITOR POL | 1 | 2 |
| R1.8K_1%_S0603 | 1 | 2 |
| R75_1%_S0603 | 1 | 2 |
### 第五步: 保存并验证
1. Ctrl+S 保存整个设计
2. Tools → Create Netlist → Allegro → OK
3. 检查 netlist.log 确认无错误
## 脚本文件
| 文件 | 说明 |
|------|------|
| diagnose_pins.tcl | 只读诊断，扫描所有 Pin 问题 |
| fix_pads_pins.tcl | 自动修复 Pin Name 重复 + 部分 Pin Number |
| debug_api.tcl | 调试用，探测 Tcl API 对象层级 |
## 技术说明
PADS 导入的简单元件(R/C/L)在 Design Cache 中是"扁平"结构:
- 正常 OrCAD: Design → Package → Device → Cell → Part (Pin Number 存在 Device 上)
- PADS 导入: Design → Part (没有 Package/Device，Pin Number 无处存放)
因此 Tcl 脚本能修复 Pin Name (存在 SymbolPin 上) 但不能修复这些 Part 的 Pin Number。
有正常 Package 结构的元件 (如 HEADER 4x1_0) 的 Pin Number 可以被脚本修复。
