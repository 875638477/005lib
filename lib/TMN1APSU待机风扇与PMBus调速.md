# TMN1APSU 待机风扇转速：能否用 PMBus / SMBus 降低

> 结论先说：**不能指望改出厂默认待机转速并永久保存。**  
> **开机后再用 I2C（PMBus 风格命令）降一档，有机会成功**，但多数实现只能降到电源固件的热保护下限，掉电后恢复默认。  
> 公开资料没有 TMN1APSU 官方通信手册，下面依据同门华为电源手册、PMBus 服务器电源规范、拆解与社区引脚信息整理，**上电前必须实测**。

---

## 1. 这颗电源是什么

| 项目 | 公开信息 |
| --- | --- |
| 型号 | TMN1APSU（部件号常见 `02312NBT`） |
| 厂商 | 华为数字能源 / 嵌入式交流电源盒 |
| 输入 | 90–290 V AC，或 190–290 V DC |
| 输出 | 53.5 V DC，约 56.1 A，额定 3000 W（低压输入会降额） |
| 通信 | 官方写明支持 **I2C**（控制、编程、监测），金手指侧有隔离 I2C |
| 风扇 | 两颗 NMB `04028DA-12V-B6K`，拆解标注 **DC 12 V / 3 A** 级 4 线 PWM |
| 使能 | 社区：金手指 **第 14 脚对地** 即可启动主路 |
| 典型用途 | 路由器 / 交换机 / 服务器 / OSN 类传输设备的交流电源盒 |

拆解还确认：二次侧有 **纳芯微 NSi8100N 双通道 I2C 数字隔离器**、两颗意法 MCU。  
所以总线物理层是有的，不是“只有模拟使能、不能说话”。

待机吵，主要不是“风扇坏了”，而是：

1. 单独使用时 **没有主机通过 I2C 接管风扇**，电源走内部保守曲线。
2. 这两颗 40×28 mm、12 V/3 A 级风扇本身极猛（同系列高转规格可到数万转、70 dB 以上）。即使固件已经在“最低档”，听感仍然快。
3. 4 线 PWM 若被电源拉到较高占空比，或控制线等效接近悬空，风扇会按规格往全速靠。

---

## 2. 直接回答三个问题

### 2.1 能不能把默认待机转速改低并保存？

**基本不行，或不值得赌。**

- 待机/空载默认转速写在电源 MCU 固件里，不是主机每次上电前能改的“出厂 EEPROM 风扇表”。
- 华为同门已公开手册的 PAC3000S12-T1、PAC800D12-B1 **命令表里没有** 标准 PMBus 的 `STORE_DEFAULT_ALL (0x11)` / `STORE_USER_ALL (0x15)`。即便某版 TMN1APSU 实现了存储命令，风扇曲线也几乎一定受热保护锁定。
- 华为交换机侧对电源风扇的官方命令是 `device power fan-speed min-value`，语义是 **抬高最低转速**（默认约 20%），不是把默认再往下压。
- PMBus 服务器电源应用规范（AC/DC Server PSU Profile）写明：`FAN_COMMAND_1 (0x3B)` **只能把风扇加快，不能低于电源自己按热设计算出的转速**。

因此：**不要指望写一次寄存器，拔电再插就永远变安静。**

### 2.2 开机后再降，行不行？

**这是唯一值得先试的软件路径。**

同门华为电源（PAC800D12-B1 / PAC3000S12-T1）都实现了：

| 命令 | 码 | 作用 |
| --- | --- | --- |
| `FAN_CONFIG_1_2` | `0x3A` | 有无风扇、按占空比还是按 RPM 下发 |
| `FAN_COMMAND_1` | `0x3B` | 写目标占空比 0–100%（Linear11）或 RPM |
| `READ_FAN_SPEED_1` | `0x90` | 读当前转速 |
| `STATUS_FANS_1_2` | `0x81` | 风扇故障 / 被覆盖 |

PAC3000S12-T1 手册还写了两句和待机直接相关的话：

- 系统可以下发命令 **关闭风扇**。
- **待机时风扇可以跑最低转速**。

TMN1APSU 没有公开同等手册，但不能排除它用同一套 PMBus 风格命令。  
实操上应：**先只读探测，确认型号和当前转速，再小步写 `0x3B`。**

预期结果分三档：

| 现象 | 含义 |
| --- | --- |
| 写 20–40% 后 `0x90` 明显下降，声音跟着下来 | 主机覆盖生效；每次上电后要再写一次 |
| 写了但转速几乎不变 | 内部热曲线盖住了，命令只允许“加快”或有硬下限 |
| NACK / 无设备 / PEC 错 | 地址、电平、是否要 PEC、或根本不是这套命令 |

### 2.3 不接主机、只插交流，风扇为什么还转得快？

电源辅电起来后，二次侧 MCU 和风扇供电就在。没有 I2C 主机时：

- 不会进入“系统已接管、按机框温度慢慢吹”的模式；
- 走内部默认曲线，空载/待机也常保持一个不低的最低占空比；
- 对 12 V/3 A 级 40 mm 风扇，这个“最低”仍然很吵。

所以：**单独当 53.5 V 砖头用，比插在原厂机框里更吵，是预期现象。**

## 3. 风扇 PWM 和转速脚电平

拆解风扇是 NMB `04028DA-12V-B6K`，4 线：红 12 V、黑 GND、白转速（Tach/FG）、棕 PWM。  
`12V-B6K` 是华为定制料号，公开手册按同系列 `04028DA` 四线规格；板上实际高电平以示波器测插头为准。

### 3.1 风扇本体（NMB 手册）

| 脚 | 方向 | 低电平 | 高电平 | 备注 |
| --- | --- | --- | --- | --- |
| PWM（棕） | 风扇输入 | **0–0.4 V** = 停（0% duty） | **3.0–5.0 V** = 满速（100% duty） | 25 kHz；**悬空 = 满速** |
| 转速 / FG（白） | 开集电极输出 | 饱和压降 **≤ 0.4 V** | **等于外部上拉电压**，自己不供高电平 | 每转 2 个脉冲；`Ic ≤ 5 mA`；`Vce` 一般可到 +30 V |
| 电源（红） | 供电 | — | **12 V**（10.8–13.2 V） | 不要和 PWM/FG 逻辑电平搞混 |

PWM 高电平上限按 Intel 4-wire 是 **5.25 V**，短路灌电流不超过约 5 mA。  
转速脚在 Intel 规范里允许主机上拉到 12 V（最大约 12.6–13.2 V），但那是主板习惯，不是风扇自己输出 12 V。

### 3.2 电源板侧（推断，未实测）

充电头网拆解主控是 **STM32F334C8T7**，`VDD` 只有 **2.0–3.6 V**，板上典型是 **3.3 V**。

因此插在 TMN1APSU 原插座上时，更可能看到：

| 信号 | 板上高电平 | 低电平 |
| --- | --- | --- |
| PWM | 约 **3.3 V**（满足 NMB ≥ 3.0 V） | ≈ 0 V / < 0.4 V |
| 转速 FG | 约 **3.3 V**（MCU 上拉，不是 12 V） | ≤ 0.4 V |

3.3 V 推挽或开漏都能驱动这颗风扇的 PWM。  
自己外接 MCU 时：PWM 用 **3.3 V** 即可，不要灌 12 V 进去；转速脚用 **4.7–10 kΩ 上拉到 3.3 V** 再读，不要上拉到 12 V 再直接进 3.3 V GPIO。

用示波器在风扇插头上量：PWM 高电平、FG 高电平，一次就能确认这台是 3.3 V 还是偶发 5 V 缓冲。

## 4. 建议的实测顺序

仓库脚本：[`scripts/tmn1apsu_fan_pmbus.py`](../scripts/tmn1apsu_fan_pmbus.py)

### 4.1 接线

1. 找到金手指上的 **SCL / SDA / SGND**（官方引脚表未公开，需对照原机背板或用万用表从 NSi8100N 隔离器次级追）。社区只确认了 **第 14 脚为使能**，不要把使能脚当成 I2C。
2. 逻辑电平按华为同门电源处理：**3.3 V**，主机侧 3–10 kΩ 上拉到 3.3 V，**不要用 5 V I2C**。
3. 时钟先用 **100 kHz**。华为手册里 `CAPABILITY (0x19) = 0x90` 表示支持 PEC、100 kHz。
4. 地址先按华为电源常见 7-bit 扫描：`0x58–0x5F`（对应 8-bit 写地址 `0xB0–0xBE`，由 A2/A1/A0 绑地决定）。悬空地址位一般为 1。

### 4.2 只读探测（先做这个）

```bash
# 需要 i2c-dev；建议在树莓派 / 工控机 / USB-I2C 适配器上跑
sudo python3 scripts/tmn1apsu_fan_pmbus.py --bus 1 --probe
```

脚本会尝试带 PEC / 不带 PEC，读取：

- `0x99` `MFR_ID`、`0x9A` `MFR_MODEL`、`0x9B` 版本
- `0x3A` 风扇配置、`0x90` 转速、`0x81` 风扇状态
- `0x8D` / `0x8E` 温度（若实现）

看到合理的厂家字符串和转速，再谈写命令。

### 4.3 开机后降速（每次上电做一次）

确认只读正常后：

```bash
# 先读当前占空比/转速，再写 30%，并回读验证
sudo python3 scripts/tmn1apsu_fan_pmbus.py --bus 1 --addr 0x58 --set-duty 30 --pec
```

建议从 **40% → 30% → 20%** 往下试，每步看：

- `READ_FAN_SPEED` 是否下降；
- 壳体 / 热点温度是否爬升；
- `STATUS_FANS` 是否出现故障位；
- 主路 53.5 V 是否还在。

写入值按 Linear11、指数 0 编码：`20% = 0x0014`，`30% = 0x001E`，`100% = 0x0064`。  
若电源把 `0x3A` bit6 配成 RPM 模式，不要按百分比写。

**不要写 `STORE_*`，不要写未知厂商命令去刷固件。**

把这条命令放到 systemd / rc.local / 自己的上电 MCU 里即可实现“开机后再降低”。掉电丢失是正常的。

## 5. 为什么不建议直接改风扇 PWM 线

拆解显示风扇是插拔 4 线，硬件上确实能在 PWM 脚另接 MCU。  
但华为同门电源会：

- 监测转速，过低或堵转超过约 10 s 报风扇故障；
- 风扇故障后 **关闭主路输出**（PAC800D12-B1 写明）；
- 用命令转速和实测转速做交叉检查。

你在电源 MCU 外面把 PWM 拉低，电源仍以为自己在按内部曲线转，很容易 **欠速告警 → 掉电**。  
要降速，优先让电源自己改 `FAN_COMMAND`，这样它的转速监控和目标是一致的。

换更安静的风扇同样有转速/电流不匹配风险，只有在你能接受主路可能被保护关掉、并且已经验证故障阈值时才考虑。

## 6. 和标准 PMBus / SMBus 的关系

- 物理层是 **SMBus/I2C**（华为写 I2C，时序按 PSMI/SMBus，常见要 PEC）。
- 命令码与 PMBus 重合（`0x3A/0x3B/0x90` 等），所以习惯上叫 PMBus。
- TMN1APSU **没有**公开确认 100% 兼容 PMBus Part I/II 或 Server PSU Profile。
- 标准 Server Profile 下，`FAN_COMMAND_1` 的语义是 **只加速**；华为部分型号允许系统关风扇或写 0–100%，但仍有温度下限。

把 TMN1APSU 当成“标准 CRPS，写 0x3B 就能静音到停转”会失望。

---

## 7. 安全

- 这是 3000 W、53.5 V 电源。金手指上既有高压相关信号，也有逻辑地，接错会烧隔离器和 MCU。
- 空载降速相对安全，**带载或壳体发烫时不要强行低于实测稳定点**。
- 风扇故障保护存在的意义是防止 GaN PFC/LLC 过热。降噪不能压过散热。
- 本文不是官方规格，引脚和命令以你手上那台的扫描结果为准。
