# bat 脚本中文乱码问题记录

## 问题现象

双击运行 `设置Cadence172环境变量.bat` 时，cmd 窗口中所有中文显示为乱码（`◆◆◆` 或 `???` 之类的字符），但脚本功能本身正常执行，环境变量设置成功。

## 原因分析

**编码不匹配**：中文 Windows 的 cmd 默认使用 **GBK（代码页 936）** 解析批处理文件，而脚本文件被保存成了 **UTF-8** 编码。

- bat 文件是 UTF-8 + cmd 按 GBK 解析 → 中文乱码
- 加 `chcp 65001`（切到 UTF-8 代码页）理论上可行，但兼容性差，且本例中文件编码与代码页仍不一致，依然乱码

## 解决办法

把 bat 文件转存为 **GBK（ANSI）编码**，并去掉 `chcp 65001` 这一行。

用 PowerShell 转换编码的命令：

```powershell
$gbk = [Text.Encoding]::GetEncoding(936)
$content = [IO.File]::ReadAllText('脚本.bat', [Text.Encoding]::UTF8)
[IO.File]::WriteAllText('脚本.bat', $content, $gbk)
```

验证编码是否正确（查看字节，GBK 的"设置"应为 `C9 E8 D6 C3`）：

```powershell
$b = [IO.File]::ReadAllBytes('脚本.bat')
($b[0..30] | ForEach-Object { '{0:X2}' -f $_ }) -join ' '
```

## 注意事项（踩坑记录）

1. **转换前必须确认源文件的真实编码**。如果文件实际是 GBK，却按 UTF-8 去读再转存，中文会变成 `?`（0x3F），且**不可逆**，只能重写文件。本次就踩了这个坑。
2. 编辑器（VSCode/Cursor）默认按 UTF-8 显示文件，GBK 编码的 bat 在编辑器里看反而是乱码——这是正常的，**以 cmd 运行效果为准**。如需在编辑器中正确查看，右下角编码选择 "GBK" 重新加载（Reopen with Encoding → GBK），但注意不要用 UTF-8 编码保存。
3. 在编辑器里修改 GBK 编码的 bat 后，保存时务必确认仍是 GBK 编码（Save with Encoding → GBK），否则又会变回 UTF-8 导致乱码。

## 经验总结

| 文件类型 | 推荐编码 | 原因 |
|---|---|---|
| `.bat` / `.cmd`（含中文） | GBK (ANSI 936) | cmd 默认按系统代码页解析 |
| `.md` / 代码文件 | UTF-8 | 编辑器、git 等通用 |
| `.ps1`（含中文） | UTF-8 with BOM | PowerShell 5.1 无 BOM 会按 ANSI 解析 |

## 补充：换行符问题（2026-06-10 第二次踩坑）

bat 编码改对了（GBK）仍然报错：`'DA365_Skill' 不是内部或外部命令`、`文件名、目录名或卷标语法不正确`。

**原因**：换行符是 LF（Unix 格式，`0A`），cmd 解析批处理必须用 CRLF（Windows 格式，`0D 0A`），否则整个文件解析错乱。

**修复命令**（PowerShell，LF 转 CRLF 并保持 GBK 编码）：

```powershell
$gbk = [Text.Encoding]::GetEncoding(936)
$c = [IO.File]::ReadAllText('脚本.bat', $gbk)
$c = $c -replace "`r`n", "`n" -replace "`n", "`r`n"
[IO.File]::WriteAllText('脚本.bat', $c, $gbk)
```

**结论**：含中文的 bat 脚本必须同时满足两个条件——**GBK 编码 + CRLF 换行符**，缺一不可。在编辑器里看右下角状态栏可同时确认这两项（编码应为 GBK，换行应为 CRLF）。
